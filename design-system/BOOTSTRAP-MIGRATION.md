Статус на 14.11.2026: **шаг 1 реализован; следующий — шаг 2**. Bootstrap-основа
собирается и включена в три production CSS bundles без флагов. Перенос экранов
не завершён. Тесты и автоматические проверки отложены до завершения визуальных
шагов. До проверки не сливать в main и не выпускать.

### Команды сборки

Node >=20.19 нужен только разработчику, не приложению или пользователю установщика.

```powershell
npm ci --prefix design-system --ignore-scripts --no-audit --no-fund
python scripts/build-ui-css.py
```

Первая команда нужна после получения checkout или изменения lock; при повторных
CSS/SCSS-правках достаточно второй. Сборка не использует npx, CDN и сетевые загрузки.
Существующий `--check` сравнивает bundles с подготовленными CSS-файлами, но не
компилирует Sass; после SCSS-изменений сначала нужна обычная сборка.

### Готовый контракт адаптера

| Наш интерфейс | Реализация Bootstrap / ограничение |
| --- | --- |
| `.vd-button`, `--primary`, `--secondary`, `--quiet`, `--danger`, `--compact` | btn и варианты через Sass extend; default/secondary тихие; без привязки к type=submit |
| `.vd-input`, `.vd-textarea`, `.vd-select` | form-control / form-select; прежние inputs/selects, aria-invalid сохраняется |
| `.vd-check`, `.vd-range` | form-check-input / form-range; native input types сохраняются |
| `.vd-tabs > [role=tab]` | nav/nav-tabs/nav-link; выбор через существующий aria-selected, не Bootstrap JS active |
| `.vd-mode-switch > button` | btn-group / компактные btn; состояние aria-pressed, без нового обработчика |
| `.vd-panel`, `.vd-badge` | card / badge; не заменяют layout и данные |
| `.vd-status`, `.vd-status--success/info/warning/danger` | alert; семантические цвета из vd-темы |
| `.vd-dialog`, file picker, progress | Native поведение; общие токены, не Bootstrap modal/custom picker |

Сами `--primary` и прочие обозначения в таблице — суффиксы полного класса,
например `vd-button vd-button--primary`. Bootstrap-классы в экраны не раздавать.

## Результат и границы

Одна визуальная основа — Bootstrap 5.3 CSS, локально, без CDN и Bootstrap JS.
HTML/JS, native WinForms/WebView2 host, редактор, backend и API остаются.
Все web-поверхности приложения входят в перенос: запись, создание, библиотека,
настройки, диагностика, диалоги и embedded/standalone отчёт. Нативные системные
окна Windows и внутренности CodeMirror не переписываются.

Не входят: React, новые функции, перестановка всего интерфейса, новые маршруты,
изменение логики меню «Вид», версии/BUILD и публикация. Не смешивать Bootstrap
с Carbon/Fluent и не воспроизводить их оформление собственными исключениями.

## Минимальная архитектура

```text
Существующие экраны и обработчики
  → наши семантические классы vd-*
  → один адаптер компонентов к Bootstrap
  → локальная зафиксированная Bootstrap CSS-основа
```

- `design-system/tokens.css` — исходные определения публичных vd-токенов;
  финальные значения экспортирует тема. Имена нужны layout и редактору;
  не создавать второй несвязанный набор или новую палитру в tokens.css.
- Новый `design-system/themes/bootstrap.scss` — единственная точка настройки
  Bootstrap: палитра, типографика, плотность, геометрия. Точные версии закреплены
  в design-system/package.json и package-lock.json, не использовать плавающий `latest`.
- Новый `design-system/bootstrap-adapter.scss` — соответствие наших классов
  Bootstrap-компонентам. Использовать Sass-механизм библиотеки, где это возможно;
  не копировать вручную её CSS и не добавлять JS, раздающий классы по всему DOM.
- `components.css` — только остающиеся специфичные компоненты приложения;
  `surfaces.css`, `workspace.css`, `editor.css`, `desktop.css` — компоновка и
  особенности поверхностей, не параллельные реализации кнопок и полей.
- `scripts/build-ui-css.py` остаётся входом сборки всех production bundles.
  Компиляция Sass — подготовка ресурсов; запуск приложения не требует Node/Sass.
  Sass установлен локально как devDependency, без lifecycle scripts.
  Системные инструменты не устанавливать; зависимости восстанавливаются явным npm ci.
- Собирать нужные части Bootstrap, не подключать целиком Reboot, grid и JS поверх
  существующего приложения. Сохранить `[hidden]`, native dialog и tab ARIA/keyboard.
- Не считать `--bs-primary` универсальной сменой темы: варианты Bootstrap имеют
  собственные переменные. Адаптер должен связывать их с общей темой явно.

Первая реализация содержит одну светлую тему. Будущая смена оформления начинается
с замены центральной темы и пересборки, без правки экранов. Runtime-переключатель,
вторая тема и гарантия замены любой библиотеки одной строкой не входят в задачу.
Новая библиотека потребует замены адаптера, но не массового переименования HTML.

## Единые роли компонентов

| Роль | Решение |
| --- | --- |
| Рабочая область | Bootstrap tabs: три вкладки на постоянном месте, активная соединена с содержимым; без «Все включённые панели» |
| Главное действие | Primary только для главного действия текущего сценария; при чтении primary не обязателен |
| Обычное действие | Нейтральный низкоакцентный вариант из общей темы |
| Вспомогательное действие | Текстовый/тихий вариант с hover и видимым keyboard focus |
| Опасное действие | Danger по смыслу операции, не общий стиль для всех кнопок |
| Поле ввода | Form control/select, без изменения типов, значений и обработчиков |
| Чтение / редактирование | Компактный переключатель режима внутри материала, ниже уровня workspace tabs |

Вариант задаётся семантическим классом, а не ID или `type=submit`.
Статус disabled остаётся отличимым; сообщения ошибок, busy и причины недоступности
не скрываются ради спокойного вида. Размеры/фокус/отступы и системный шрифт — по
обновлённому MASTER, не по индивидуальным решениям исполнителей.

## Пять последовательных шагов

Каждый шаг — один ограниченный handoff. Не запускать параллельное редактирование.

### 1. Основа и контракт

**Файлы:** MASTER.md, CONTRACTS.md, этот план; новые theme/adapter/vendor resources,
build configuration/lock, `scripts/build-ui-css.py`, нужные third-party notices.

Закрепить версию и MIT notices; добавить локальную сборку и таблицу соответствий
vd → Bootstrap для кнопок, полей, tabs, переключателя режима, статусов и панелей.
Экраны не менять; включить основу последним слоем всех трёх CSS bundles без флага.
В MASTER заменить противоречащие текущие правила, а не дописать ещё один стиль.
Не редактировать AGENTS.md/skills: если это потребуется, сначала отдельно описать изменения.

**Готово:** есть один путь сборки и одна тема; нет дополнительной UI-библиотеки.

### 2. Запись и встроенный редактор — один образец

**Файлы:** общие design-system CSS/SCSS, `video_descriptor/assets/create.html`,
`report-embed.js`, `recording.js`, `editor.js`, `speech-edit.js` только в местах
создания разметки; `design-system/pages/workspace.md`.

Применить роли к цепочке «вкладки → версия → действия → редактор» и диалогу реплики.
Общая основа уже включена в bundles. Убрать заменённые временные стили вкладок и
точечные исключения для кнопок «Открыть / Создать». Не менять state owners,
dirty guards, material selection, iframe/player lifecycle или меню «Вид».

**Готово:** весь видимый участок, включая iframe toolbar, оформлен одной системой.
Пауза для ручного просмотра. Зафиксировать один выбранный вариант, не делать
несколько циклов косметической настройки без конкретной проблемы.

### 3. Настройки, создание и библиотека

**Файлы:** `windows-app/ui/` HTML/JS/layout, `video_descriptor/assets/create.html`,
общие styles, `video_descriptor/library.py` только HTML-разметка; page overrides.
Перед работой прочитать scoped AGENTS.md и overrides этих поверхностей.

Перенести поля, кнопки, settings tabs, панели подготовки/диагностики, библиотеку
и диалоги. Сохранить загрузку файлов, формы, IDs, handlers, consent и busy states.
JS менять только для классов создаваемых controls; Python — только presentation.

**Готово:** основные полные страницы используют ту же тему без локального дизайна.

### 4. Отчёты и оставшиеся поверхности; убрать старое

**Файлы:** `video_descriptor/report.py` только HTML/resources, editor assets/styles,
help HTML generators и их общие ресурсы, shared CSS, сборка, затронутые overrides.

Охватить standalone отчёт, динамические controls, помощь и оставшиеся диалоги.
Включить оформление в новые переносимые отчёты без внешних ресурсов. Старые
сохранённые отчёты не регенерировать и не переписывать. CodeMirror/EasyMDE сохранить;
адаптировать только внешние поверхности и toolbar без замены editor engine.
Удалить заменённые определения компонентов из старых styles. Не чинить конфликты
накоплением `!important` и длинных ID-селекторов. Оставить feature-specific layout.

**Готово:** один владелец внешнего вида каждого компонента; нет известной пропущенной
поверхности. Если обнаружена новая — назвать её и перенести в этом шаге, без нового эпика.

### 5. Ручной просмотр и завершение документации

**Файлы:** тема/адаптер для конкретных замечаний, MASTER, CONTRACTS, page overrides,
WORKSPACE-TABS, UI-UX-EPIC и development/history; operational guides при изменении сборки.

Один проход: запись/материалы, редактор, создание, настройки, библиотека и standalone
отчёт. Вносить только понятные исправления: потерянный control, обрезанный текст,
слабая иерархия, невидимый focus или конфликт CSS. Новые функции не добавлять.
Документировать команду сборки, точку смены темы и известные ограничения.

**Стоп:** оформление цельное, controls доступны, нет дублирующих стилей. Не добиваться
пиксельного совпадения со всеми примерами Bootstrap. Статус — «визуальный перенос
завершён, автоматическая проверка отложена», а не «готово к выпуску».

## Отложенная проверка

В шагах 1–5 не писать/запускать тесты, Fast, audit, браузерную автоматизацию или
обновлять baseline ради нового вида. Пересборка CSS нужна для отображения, но
не является доказательством корректности. Отдельный последующий шаг: имеющиеся
focused UI scenarios, CSS/UI contracts и Fast; добавить только отсутствующие
регрессии темы/адаптера. Известный конфликт вкладок с меню «Вид» не считать решённым.
Merge/релиз не входят в визуальные шаги.

## Короткий handoff для любой модели

> Выполни только шаг N из design-system/BOOTSTRAP-MIGRATION.md. Прочитай указанные
> контракты и scoped AGENTS.md. Не перепроектируй выбранный подход. Сохрани текущие
> незакоммиченные правки. Меняй только presentation и ресурсы своего шага; если
> требуется изменение поведения, остановись и назови причину. Не добавляй вторую
> библиотеку, React, новые функции или систему раздачи CSS-классов через JS.
> Тесты и проверки отложены; CSS пересобери для просмотра. В конце кратко перечисли
> результат, затронутые поверхности, блокеры и следующий шаг. Не заявляй проверенный PASS.
