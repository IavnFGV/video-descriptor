# Video Descriptor — единая дизайн-система v0.1

Статус: **направление согласовано владельцем 19.10.2026**. Production библиотека, workspace, редакторы, диалоги и экспорт внедрены: см. IMPLEMENTATION.md. Стек: HTML, CSS, JavaScript, WebView2. Источник токенов: `tokens.css`; реализация компонентов: `components.css`; демонстрация: `prototype/index.html`.

## Принципы

1. Одна запись — одно рабочее пространство: источник → расшифровка → перевод / конспект → экспорт.
2. Основное действие одно на область. Настройки находятся рядом с этапом, глобальные подключения — в настройках приложения.
3. Готовность компонента, ход операции и статус задания — разные сущности. Не обещать готовность генерации по наличию установленной модели.
4. Состояние выражается текстом и формой, цвет дополняет его. Рабочие данные, ошибки и названия файлов важнее декоративных слоганов.
5. Системный шрифт, локальные ресурсы, нативные file/select/dialog. Не добавлять framework, Tailwind, внешний CDN или icon font.

Светлая тема — первый релиз. Dark theme не заявляется как готовая: нужен отдельный полный набор токенов и проверка media/select/editor. `color-scheme: light` предотвращает случайное смешение тем Windows. Числа времени/прогресса — tabular-nums. Нельзя делать служебный текст полупрозрачным ради «лёгкости».

## Контракты компонентов

| Компонент | Семантика и варианты | Поведение и состояния |
|---|---|---|
| Button `.vd-button` | `<button type=button>`; primary, secondary (default), quiet, danger | default, hover, pressed, focus-visible, disabled, busy; busy: `aria-busy=true`, текст «Сохраняем…», блокировать повторную отправку; причина disabled рядом |
| Link `.vd-link` | `<a href>` для маршрута, документа или прямой загрузки | underline в тексте; hover/focus; download — `download`; внешний переход только через разрешённый host-механизм; нет `href="#"` для команд |
| FilePicker `.vd-file` | label + доступный `input[type=file]` + имя + ограничения + сообщение | одинаковая оболочка для медиа и WAV, разные accept/лимиты; мышь, Tab/Space, drop; одна функция валидации для обоих путей; отмена сохраняет предыдущий выбор; ошибка не стирает имя |
| FolderPicker | текстовый input пути + secondary «Выбрать папку…» | использует существующий Windows `/api/setup/pick-model`; file input не заменяет выбор папки; результат ещё не означает inspect/verified |
| Field / Select `.vd-field` | label[for], name, input/select/textarea; help/error через aria-describedby | read-only, disabled, invalid (`aria-invalid`); ошибки у поля, focus первого ошибочного; native select, без самодельного listbox |
| Dialog `.vd-dialog` | native `<dialog>` + aria-labelledby + showModal | initial focus, Escape/Отмена, возврат фокуса; scroll внутри, max-height 90dvh; один primary; удаление: фокус на отмене; не терять введённые данные при ошибке |
| Status `.vd-status` | текст + необязательная декоративная SVG-иконка | neutral/queued, info/running, success/done, danger/error, warning/unavailable; готовность хранится отдельно; aria-live на сообщении, не на всей странице |
| Progress `.vd-progress` | `<progress>` с label | upload/model bytes отдельно от обработки; value только при известном знаменателе; без value — неопределённый ход; рядом этап, значение, возможность восстановления; не выдумывать ETA |
| Tabs | button role=tab + tablist + tabpanel | один tabIndex=0, aria-selected/controls; Left/Right/Home/End; URL stage, сохранение job/folder/report; не заменять ссылками при локальном переключении панели |
| Record row | ссылка на запись с именем и статусом | доступное полное имя, перенос длинных имён, текущая aria-current; фильтры/версии не теряют выделение |
| Disclosure | native details/summary | только дополнительные параметры, не прятать обязательный следующий шаг и ошибки |

Текстовая кнопка «Обновить» остаётся кнопкой, даже если выглядит как ссылка. SRT/VTT/TXT используют одинаковый link download, Markdown из несохранённого редактора — button, поскольку собирается из текущего текста. Кнопочный вид допустим у `<a>` при реальном href. Семантика определяется действием, а не внешним видом.

## Навигация и действия

Постоянная левая панель: **Записи**, **Настройки AI**, **Диагностика**. «Новая запись» — primary на пустой библиотеке / toolbar библиотеки. В рабочем пространстве — заголовок записи, выбор версии, этапы **Источник / Расшифровка / Конспект**. Перевод — действие/режим расшифровки; отдельный маршрут перевода на первом этапе не нужен. Экспорт — единая панель готового результата. Ошибки задания — рядом с этапом и действием «Продолжить из кэша».

Маршруты следующего этапа: сохранять `/`, `?job=`, `/create?folder=&stage=&report=`; библиотеку и настройки сначала оформить внутри существующих страниц. Новые маршруты и история Back/Forward требуют отдельного согласованного изменения роутинга. В прототипе только локальные `#records`, `#settings`, `#diagnostics`; это не новые backend endpoints.

Главный экран создания: короткий h1 «Новая запись», выбор файла, название/язык, раскрываемые параметры распознавания, один primary «Расшифровать запись». Готовность в компактной панели с понятным следующим шагом. Устройство явно доступно пользователю: AUTO → NPU → GPU → CPU; никакой молчаливой подмены явного выбора. Подключения Ollama/Gemini и промпты не занимают область главного действия.

Настройка AI: обязательные **компоненты → модель → подготовка → проверка**; необязательные **Ollama / Gemini / OCR / голоса** отдельно. Пропуск не выдаёт ложную готовность. Скачивание требует существующего согласия и показывает источник/размер до запуска. «Закрыть окно» и «Остановить приложение» разные команды; остановку вынести в меню приложения, сохранив backend 409 при активной очереди.

Редактор: основной action «Сохранить правки»; secondary «Экспорт»; перевод/новый конспект создают версию и сохраняют исходную. Удаление версии/конспекта — danger в меню, со существующим подтверждением. План/провайдер/промпт конспекта — в настройках этапа, не среди экспортов.

## Адаптация и доступность

При 1200×820 — nav + workspace + узкая readiness; при ≤1000 — readiness под формой; при ≤800 — nav в горизонтальный ряд, без sticky-плеера; при 375 — поля в столбец. Обязательные acceptance: окно host минимум 760×560, 1024×768, 1200×820, 1440×900, Windows scaling 125/150/200%, zoom 200%, длинные RU/UK имена. Навигация и фокус не перекрываются sticky-элементами. Основной текст ≥4.5:1, крупный ≥3:1, элементы/focus ≥3:1; проверять реальные пары, а не только палитру. Tab/Shift+Tab, Enter/Space, Escape; без hover-only действий. SVG 20/24 px, aria-hidden; icon-only обязательно aria-label. Skip link к main. Не использовать emoji как иконки.

## Обязательность для дальнейших изменений

`AGENTS.md` в корне и в `windows-app/ui/` направляют разработчика сюда. Каждая UI-задача читает MASTER и page-specific overrides до правок. Новые значения сначала добавляются в tokens.css с обоснованием; raw цвета и локальные стили компонентов не добавляются. Исключения документируются в `pages/<screen>.md`; при конфликте сначала явное решение, затем код. Эти правила применяются и к `video_descriptor/assets`, генерируемым отчётам и библиотеке.

Перед переносом компонента: проверить DOM/API manifest, keyboard, ошибки, pending/disabled, empty/long content и визуальный diff. Проверка исходных SHA на первом этапе доказывает отсутствие изменений; на следующих этапах её нельзя обходить обновлением baseline без contract-review. Для главной `scripts/build-ui-css.py` собирает общие tokens/components и scoped layout в существующий app.css. Не редактировать generated bundle вручную; `--check` обязателен. Для других экранов предварительно устранять заменяемые широкие CSS-селекторы.

## Основания решений

Использованы локальный `ui-ux-pro-max` (design-system + ux + html-tailwind search) и [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md), получены 19.10.2026. Автовыдача Pro Max предложила landing/video hero, оранжевый CTA и Lora/Raleway; эти рекомендации отклонены: desktop-продукту нужен плотный рабочий экран, локальный системный шрифт и единый акцент. Приняты focus, recovery, native forms, progress, reduced motion. Tailwind-рекомендации переведены в обычный CSS, зависимость не добавлена. Слова о росте engagement из генератора не являются исследованием этого продукта.
