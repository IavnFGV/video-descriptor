# Video Descriptor — единая дизайн-система

## Основа оформления: Bootstrap 5.3

Текущий перенос использует только Bootstrap 5.3.9 CSS, без React, Bootstrap JS,
Carbon или Fluent. [План и статус](BOOTSTRAP-MIGRATION.md) — точка передачи шагов.
Основа подключена ко всем трём CSS bundles сразу, без флага или старого режима.
Роли основных поверхностей перенесены в шагах 2–4; широкий fallback для кнопок
и полей удалён. [Визуальный проход в Edge](BOOTSTRAP-REVIEW.md) выполнен;
технические результаты — в том же отчёте; installed WebView2 не проверен.

`themes/bootstrap.scss` — единственная настройка новой темы и экспорт публичных
`--vd-*` токенов. `bootstrap-adapter.scss` связывает наши семантические классы
с реальными стилями Bootstrap через Sass. `bootstrap.css` и production bundles
генерируются `scripts/build-ui-css.py`; не редактировать их вручную.
`tokens.css` временно сохраняет исходные определения; финальные значения темы
экспортируются последним слоем. Не добавлять туда вторую палитру или новые
переопределения компонентов: изменения нового оформления делаются в теме/адаптере.

Внешний вид не назначается по DOM ID, `type=submit` или JS-декоратором страницы.
Доступные `.vd-tabs > [role=tab]` используют `cursor:pointer`; у disabled и
`aria-disabled=true` остаётся обычный указатель. Правило задаёт общий адаптер.
Роль задаётся классом: primary — главное действие сценария, secondary — обычное,
quiet — вспомогательное, danger — опасное. Экран чтения может не иметь primary.
Вкладки используют Bootstrap nav-tabs: выбранная вкладка соединяется с поверхностью
контента. Чтение/редактирование — компактный переключатель внутри материала,
а не ещё одна контекстная навигация. Состояния и layout остаются у текущих owners.

## Текущая desktop-композиция

Общая оболочка и её карта переходов описаны в [плане унификации](SHELL-UNIFICATION.md).
На Windows все полные страницы используют одинаковые команды обновления и выхода;
«Новая запись» и «Записи» всегда открывают чистую форму и библиотеку без query
предыдущего документа. Shared web не показывает Windows-команды, настройки и
диагностику Windows host; «Справка» там открывает общий диалог напрямую.
File-отчёт не обращается к серверу и не показывает онлайн-меню; embedded без шапки.
Старые сохранённые отчёты остаются с прежними assets; известные controls получают
роли адаптера в embedded HTTP-ответе, без записи на диск. Визуальный проход
выполнен, границы проверки — в [отчёте](BOOTSTRAP-REVIEW.md).

«Вид» показывается только при открытой записи; вне записи меню
скрыто, а сохранённые настройки остаются доступными при следующем открытии.

Постоянной левой панели и её переключателя нет.
Единая верхняя строка на всех полных страницах: Файл (новая запись, записи),
Вид (preferences панелей открытой записи), Инструменты (настройки AI и подключения,
диагностика), Справка (помощь и инструкции подключения). Не создавать меню
из одного пункта. Подключения всегда используют общую форму Ollama / LM Studio
и Gemini в настройках, а не устаревший диалог записи. Рабочая область занимает
освободившуюся ширину. Скрытые legacy IDs/handlers не означают видимый sidebar.

Редизайн оболочки внедрён без смены backend, редакторов, маршрутов или framework.
Решения, история изменений и снимки: [DESKTOP-REDESIGN.md](DESKTOP-REDESIGN.md).
Команды «Файл / Вид / Инструменты / Справка» — в общей строке высотой 44 px;
Записи находятся в «Файле», настройки AI и диагностика — в «Инструментах».
«Вид» использует прежний контроллер и preferences. Заголовок документа — 22 px;
рабочая область видео/речи — 40/60 на широком окне, вертикальная до 1000 px.
Desktop layout primitives живут в `desktop.css`; после них собирается общая Bootstrap-основа.
Формы сохраняют controls 40 px, рабочие toolbar — 32 px. Цвета и типографическая
шкала прежние. Новый radius панелей 8 px и 44 px chrome имеют именованные токены.
Прототип `prototype/desktop-shell.html` не обращается к API.

Обязательное правило UI (09.11.2026): между полем и связанными с ним кнопками, а также между кнопками одной группы — 8 px (`--vd-control-gap`); между самостоятельными группами — 16 px (`--vd-group-gap`). Поле с действиями оформлять `.vd-control-group`, кнопки — `.vd-actions`. Едино для приложения, настроек, библиотеки, диалогов и отчётов; CSS собирать из общих источников. Не компенсировать отступы пробелами в HTML или отдельными случайными margin.

Production библиотека, workspace, редакторы, диалоги и экспорт внедрены: см. IMPLEMENTATION.md. Стек: HTML, CSS, JavaScript, WebView2. Тема и роли компонентов — в Bootstrap-основе выше; `components.css` содержит сохраняемые специфичные компоненты. `prototype/index.html` — историческая демонстрация, не новый визуальный эталон.

## Принципы

1. Одна запись — одно рабочее пространство: источник → расшифровка → перевод / конспект → экспорт.
2. Основное действие одно на область. Настройки находятся рядом с этапом, глобальные подключения — в настройках приложения.
   В Windows повторное распознавание запускается пунктом создания в списке версий; отдельной
   формы «Настройки речи» нет, модель и устройство берутся из настроек AI.
   Shared web сохраняет форму выбора обработчика; подробности — в [workspace override](pages/workspace.md).
3. Готовность компонента, ход операции и статус задания — разные сущности. Не обещать готовность генерации по наличию установленной модели.
4. Состояние выражается текстом и формой, цвет дополняет его. Рабочие данные, ошибки и названия файлов важнее декоративных слоганов.
5. Системный шрифт, локальные ресурсы, нативные file/select/dialog. Не добавлять framework, Tailwind, внешний CDN или icon font.

## Контракты компонентов

| Компонент | Семантика и варианты | Поведение и состояния |
|---|---|---|
| Button `.vd-button` | `<button>` с прежним type; default/secondary — нейтральный, primary — главное действие, quiet — вспомогательное, danger — опасное; без нового поведения | default, hover, pressed, focus-visible, disabled, busy; busy: `aria-busy=true`, текст «Сохраняем…», блокировать повторную отправку; причина disabled рядом |
| Link `.vd-link` | `<a href>` для маршрута, документа или прямой загрузки | underline в тексте; hover/focus; download — `download`; внешний переход только через разрешённый host-механизм; нет `href="#"` для команд |
| FilePicker `.vd-file` | label + доступный `input[type=file]` + имя + ограничения + сообщение | одинаковая оболочка для медиа и WAV, разные accept/лимиты; мышь, Tab/Space, drop; одна функция валидации для обоих путей; отмена сохраняет предыдущий выбор; ошибка не стирает имя |
| FolderPicker | текстовый input пути + secondary «Выбрать папку…» | использует существующий Windows `/api/setup/pick-model`; file input не заменяет выбор папки; результат ещё не означает inspect/verified |
| Field / Select `.vd-field` | label[for], name, input/select/textarea; help/error через aria-describedby | read-only, disabled, invalid (`aria-invalid`); ошибки у поля, focus первого ошибочного; native select, без самодельного listbox |
| Dialog `.vd-dialog` | native `<dialog>` + aria-labelledby + showModal | initial focus, Escape/Отмена, возврат фокуса; scroll внутри, max-height 90dvh; один primary; удаление: фокус на отмене; не терять введённые данные при ошибке |
| Status `.vd-status` | текст + необязательная декоративная SVG-иконка | neutral/queued, info/running, success/done, danger/error, warning/unavailable; готовность хранится отдельно; aria-live на сообщении, не на всей странице |
| Progress `.vd-progress` | `<progress>` с label | upload/model bytes отдельно от обработки; value только при известном знаменателе; без value — неопределённый ход; рядом этап, значение, возможность восстановления; не выдумывать ETA |
| Tabs `.vd-tabs` | button role=tab + tablist + tabpanel; Bootstrap nav-tabs через общий адаптер, без Bootstrap JS | один tabIndex=0, aria-selected/controls; Left/Right/Home/End; URL stage, сохранение job/folder/report; не заменять ссылками при локальном переключении панели |
| Record row | ссылка на запись с именем и статусом | доступное полное имя, перенос длинных имён, текущая aria-current; фильтры/версии не теряют выделение |
| Disclosure | native details/summary | только дополнительные параметры, не прятать обязательный следующий шаг и ошибки |

Текстовая кнопка «Обновить» остаётся кнопкой, даже если выглядит как ссылка. SRT/VTT/TXT используют одинаковый link download, Markdown из несохранённого редактора — button, поскольку собирается из текущего текста. Кнопочный вид допустим у `<a>` при реальном href. Семантика определяется действием, а не внешним видом.

## Навигация и действия

В открытой записи общий ряд «Расшифровка / Конспект / Статья / Сведения / Обработка» находится справа
от видео, до 1000 px — под ним. Визуальный черновик Task 10 убирает «Все включённые
панели»; вкладки используют Bootstrap nav-tabs. Из меню «Вид» убран устаревший
технический пункт; согласование остальных checkbox-controls с вкладками отложено.
Прежние запросы совместимого вида открывают расшифровку. Проверка паритета остальных
сочетаний меню с вкладками отложена. Поведение выбора, guards и маршрутов — в
[workspace override](pages/workspace.md).

«Сведения» содержит данные файла и переименование независимо от technical preference.
Выбор версии и кнопка «Удалить» находятся внутри соответствующей вкладки
«Расшифровка / Конспект / Статья». Общий `.recording-version` задаёт одинаковые
полужирные подписи и поля; кнопка справа сразу открывает подтверждение, без меню.
Каждый список содержит пункт создания; готовая версия отображается сразу при
выборе, без отдельных кнопок «Открыть» и «Создать» возле списка.
Предупреждение о частичном распознавании —
также возле расшифровки. Отдельная вкладка «Обработка» содержит запрос,
рассуждения, текущий ответ модели и журнал, независимо от technical preference.
Краткий прогресс, остановка, ошибки и восстановление остаются вне вкладок.
«Открыть журнал» возле ошибки раскрывает журнал и переводит туда фокус;
если журнала ещё нет, фокусирует пояснение отсутствия данных или саму панель.
Блока «Ход обработки» с дублирующим статусом во вкладке нет.
Промпты редактируются только в формах создания конспекта/статьи. Централизованный
редактор вспомогательных задач и ссылка на него из запроса убраны из UI;
legacy настройки, черновики и backend сохранены без фоновой загрузки старого редактора.

Навигация — в верхних меню, без постоянной левой панели. «Новая запись» — primary на пустой библиотеке / toolbar библиотеки. В открытой записи — общий плеер, расшифровка и независимый выбор версий речи и материалов; конспект/статья используют один редактор. Перевод временно убран из UI без удаления сохранённых данных и backend. Прежние stage IDs/query сохранены, но полоса трёх этапов скрыта в открытой записи. Экспорт — при соответствующем результате; ошибки и продолжение остаются вне скрываемых областей.

Сохранять `/`, `?job=`, `/create?folder=&stage=&report=`, существующие hash-маршруты и Back/Forward. Не добавлять маршруты при визуальных правках: изменения роутинга — отдельная задача. Исторический прототип использует локальные `#records`, `#settings`, `#diagnostics`; он не определяет новые backend endpoints.

Главный экран создания: короткий h1 «Новая запись», выбор файла, название/язык, раскрываемые параметры распознавания, один primary «Расшифровать запись». Готовность в компактной панели с понятным следующим шагом. Устройство явно доступно пользователю: AUTO → NPU → GPU → CPU; никакой молчаливой подмены явного выбора. Подключения Ollama/Gemini и промпты не занимают область главного действия.

Настройка AI: **компоненты → модель → подготовка → проверка** для выбранных функций; необязательные **Ollama / LM Studio / Gemini / OCR / участники** отдельно. Первый запуск не навязывает мастер и не начинает загрузку без действия пользователя. Пропуск не выдаёт ложную готовность. Скачивание показывает источник/размер и требует согласия. «Закрыть окно» и «Остановить приложение» разные команды; остановка — в «Файле», с backend 409 при активной очереди.

Редактор: в режиме правки основной action «Сохранить правки»; экспорт — вспомогательное действие; в режиме чтения акцентная кнопка не обязательна. Новый конспект/статья создают версию и сохраняют исходную. Удаление версии расшифровки/конспекта/статьи — danger-кнопка рядом с выбором версии, с подтверждением. План/провайдер/промпт конспекта — в настройках этапа, не среди экспортов.

## Адаптация и доступность

В открытой записи корневой документ резервирует место под вертикальную полосу
прокрутки (`scrollbar-gutter: stable`). Переключение коротких и длинных вкладок
не меняет ширину сетки, видео и области содержимого; поведение — в workspace override.

На широком окне видео/речь — 40/60; до 1000 px или при выборе вертикального вида — друг под другом. Верхние меню остаются общей навигацией; панели раскрываются поверх содержимого без изменения высоты строки. При 375 px поля располагаются в столбец. Видео не закрепляется поверх материалов. Обязательные acceptance: окно host минимум 760×560, 1024×768, 1200×820, 1440×900, Windows scaling 125/150/200%, zoom 200%, длинные RU/UK имена. Это требования проверки, не заявление о пройденной приёмке. Навигация и фокус не перекрываются sticky-элементами. Основной текст ≥4.5:1, крупный ≥3:1, элементы/focus ≥3:1; проверять реальные пары, а не только палитру. Tab/Shift+Tab, Enter/Space, Escape; без hover-only действий. SVG 20/24 px, aria-hidden; icon-only обязательно aria-label. Skip link к main. Не использовать emoji как иконки.

## Обязательность для дальнейших изменений

`AGENTS.md` в корне и в `windows-app/ui/` направляют разработчика сюда. Каждая UI-задача читает MASTER и page-specific overrides до правок. Новые значения оформления добавляются в `themes/bootstrap.scss`, новые связи компонентов — в общий адаптер; raw цвета и локальные стили компонентов на экранах не добавляются. Исключения документируются в `pages/<screen>.md`; при конфликте сначала явное решение, затем код. Эти правила применяются и к `video_descriptor/assets`, генерируемым отчётам и библиотеке.

Проверка переноса компонента охватывает DOM/API manifest, keyboard, ошибки, pending/disabled, empty/long content и визуальный diff. В текущих визуальных шагах Bootstrap автоматическая проверка отложена по плану; это не PASS и не основание обновлять baseline. `scripts/build-ui-css.py` компилирует Bootstrap Sass и собирает общие tokens/components/layout с адаптером последним слоем. Не редактировать generated bundle вручную. Перед последующей проверкой с `--check` сначала пересобрать SCSS. Заменяемые широкие CSS-селекторы удалять, а не перекрывать дополнительными исключениями.

## Основания решений

Использованы локальный `ui-ux-pro-max` (design-system + ux + html-tailwind search) и [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md), получены 19.10.2026. Автовыдача Pro Max предложила landing/video hero, оранжевый CTA и Lora/Raleway; эти рекомендации отклонены: desktop-продукту нужен плотный рабочий экран, локальный системный шрифт и единый акцент. Приняты focus, recovery, native forms, progress, reduced motion. Tailwind-рекомендации переведены в обычный CSS, зависимость не добавлена. Слова о росте engagement из генератора не являются исследованием этого продукта.
