## Метод и охват

Отдельный headless Edge с временным профилем, управление через CDP и реальные
нажатия мыши/клавиатуры. Скриншоты просмотрены после завершения CSS transitions.
Размер окна браузера согласован с эмулируемым viewport, device scale factor — 1.
Это не проверка установленного WinForms/WebView2 и не Windows scaling acceptance.

| --- | --- | --- |
| Локальное приложение, `main` | Библиотека, новая запись, Файл/Инструменты/Справка, все семь вкладок настроек, обе инструкции, `/output/`, keyboard skip link | 20 |
| Локальная запись, `recording` | Расшифровка, меню «Вид», существующая статья | 6 |

Просмотрены состояния на 1440×900, 1024×768, 760×700 и 375×800; не каждое
состояние снималось во всех размерах. Редактор на узком экране прокручен к его
controls, а не оценён только по верхней части страницы.

Во всех 39 снимках `scrollWidth` не превышает ширину viewport; JavaScript exceptions,
unhandled rejections и ошибки console.error не зафиксированы. У общей шапки высота
44 px; embedded editor не создаёт вложенную шапку. В сетевых ответах отмечен
404 `/favicon.ico`, не влияющий на просмотр. У временного сервера наблюдался
разрыв загрузки медиа при переходе на другую страницу; сценарий продолжился.
Проверены 132 локальные Markdown link targets изменённых документов; отсутствующих нет.

## Исправления

1. Убрано старое `min-height:64px` нативной topbar, конфликтовавшее с общей высотой
   44 px. Теперь главная, запись и справка используют одинаковую высоту шапки.
2. Skip links `.skip`/`.vd-skip` используют одно определение в `components.css`:
   скрыты до focus, при Tab видимы под фиксированной шапкой. При создании шапки
   ссылка остаётся перед меню в DOM; новые отчёты получают ссылку к материалу.
3. Статус записи использует `.vd-status`/`data-tone` вместо сырого `.badge`.
   Конфликт Bootstrap с прежним светлым фоном больше не делает текст нечитаемым.
4. `report.with_editor_control_roles` добавляет семантические роли только известным
   старым editor controls и переключателю режима при выдаче embedded HTTP-ответа.
   Это не новый набор стилей и не JS-декоратор страницы. Сохранённые HTML/assets
   не регенерируются; текущий stylesheet оформляет старую разметку без fallback
   для всех кнопок. DOM ids и handlers сохраняются.
5. У доступных вкладок общий адаптер явно задаёт `cursor:pointer`, у disabled —
   `default`. Дополнительный Edge-проход подтвердил computed cursor для семи вкладок
   настроек, трёх workspace-вкладок и disabled-состояния на изолированных данных.

## Защита данных и проверенные действия

- В браузере блокировались все не-read HTTP-запросы и внешние ресурсы. Запуск
  обработки, загрузка моделей, сохранение результатов и выход не выполнялись.
- Автоматический POST `/api/construction-plan` локальной страницы перехвачен до
  отправки. Отсутствующий конспект не создавался; его редактор проверен на fixture.
- Ошибка диалога обновлений просмотрена только на fixture: POST
  `/api/updates/check` заблокирован. Надпись о недоступном GitHub в этом снимке
  не является свидетельством реального сбоя GitHub.
- В демонстрационном документе введён несохранённый текст. Попытка уйти через
  «Новая запись» оставила документ на месте, меню открытым, focus на пункте;
  `notesEditorDirty()` оставался true. Правка отменена через Ctrl+Z, без сохранения.
- SHA-256 одного просмотренного пользовательского `report.html` до/после прохода
  совпал. SHA-256 fixture с legacy markup также не изменился после выдачи с новыми
  ролями; роли mode/save/export присутствовали в DOM ответа.
- Временный HTTP-процесс preview перезапущен для Python presentation-изменений.
  Worker и NPU-сервис не останавливались.

Артефакты находятся вне Git в `<TEMP>/opencode/vd-bootstrap-review-20261114/`:
`main-report.json`, `recording-report.json`, `fixture-report.json`, снимки и

- Отдельное offline file-открытие экспортированного отчёта: standalone просмотрен
