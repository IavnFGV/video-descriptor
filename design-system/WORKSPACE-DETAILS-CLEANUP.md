# Очистка технических блоков записи

Дата: 14.11.2026. Статус: план; интерфейс ещё не изменён.

Цель: убрать служебные формы из повседневного просмотра записи. Добавить одну
вкладку «Сведения» справа от «Статьи» в существующем ряду, без постоянной боковой
панели и без нового framework или backend API.

Текущее поведение описано в [workspace override](pages/workspace.md) и
[контрактах](CONTRACTS.md). Этот файл описывает предстоящие изменения, а не
заменяет действующие контракты. По завершении каждого шага обновлять его статус,
текущие руководства и проверки в том же изменении.

## Что обнаружено в реализации

Переключатель «Вид → Технические сведения и параметры» управляет несколькими
независимыми областями, а не одной панелью:

| Область | Содержимое | Целевое место |
| --- | --- | --- |
| Настройки речи | Обработчик, пояснение, создание новой версии речи | Удалить форму из Windows UI; повторный запуск оставить отдельным действием без формы |
| Сведения о файле | Имя файла, длительность, распознанный диапазон, доступность источника, частичный охват, изменение названия | «Сведения → Файл» |
| Меню версии внутри сведений о файле | Удаление выбранной версии | Возле выбора версии, отдельно от характеристик файла |
| Подробности обработки (`diagnostics`) | Этап, статистика, точный запрос, рассуждения, непроверенный ответ, переключатель рассуждений, журнал | «Сведения → Обработка» |
| Вторые подробности обработки (`recording-processing`) | Сводка и блоки перевода, скрытые в текущем UI | Не создавать отдельный пустой блок; исторические сведения объединить с обработкой при наличии |
| Промпты вспомогательных задач | Выбор задачи, инструкция, сохранение, возврат стандартного текста | «Сведения → Дополнительно → Инструкции модели», свёрнуто |

### Почему форма настроек речи лишняя в Windows

В исходной HTML-разметке есть несколько обработчиков, но Windows-инициализация
в `recording.js` заменяет список единственным `whisper-local`: «Локальное
распознавание · устройство из настроек AI». Модель и устройство выбираются в общих
настройках AI, а не в этой форме. Фактически форма содержит пояснение и кнопку
повторного запуска. Смена значения сама по себе не меняет готовую расшифровку.

Сейчас пункт «Создать новую расшифровку…» в выборе версий включает всю группу
технических областей через `setPanel('technical', true)`, затем раскрывает форму.
Эту связь необходимо убрать.

В shared web список обработчиков не заменяется одним вариантом. Удаление Windows
формы не должно случайно сломать выбор обработчика в web или загрузку новой записи:
`create.js` также читает `speech-engine`. Удаление DOM-узлов требует проверки всех
обращений, а не только скрытия или удаления HTML.

## Пошаговый план

### Шаг 0. Зафиксировать разбор

- [x] Проверить состав технических областей по HTML, JavaScript и CSS.
- [x] Сохранить целевую структуру и последовательность в этом файле.
- [ ] Проверить поведение в работающем интерфейсе; исходный разбор статический.

### Шаг 1. Убрать форму «Настройки речи» из Windows

- [ ] Удалить видимую форму с единственным обработчиком и дублирующим пояснением.
- [ ] Сохранить отдельное явное действие «Создать новую расшифровку» с текущей
  моделью и устройством из настроек AI, без дополнительной формы и без открытия
  технических блоков. Не запускать обработку от простого просмотра вкладки.
- [ ] Сохранить старые версии, запрет повторного запуска при активном задании,
  защиту несохранённых правок и понятное сообщение об ошибке.
- [ ] Проверить создание новой записи и shared web; не удалять используемые
  обработчики и DOM IDs вслепую.

### Шаг 2. Добавить вкладку «Сведения» и перенести файл

- [ ] Добавить вкладку после «Статьи» в существующий ряд справа от видео;
  на узком окне использовать ту же адаптивную компоновку.
- [ ] Перенести существующие сведения о файле и изменение названия в раздел «Файл».
- [ ] Оставить удаление версии возле выбора версии, с прежним подтверждением.
- [ ] Сохранить предупреждение о частичном распознавании также возле расшифровки:
  оно влияет на понимание результата и не должно быть видно только в сведениях.
- [ ] Проверить клавиатуру, выбранную вкладку, возврат и несохранённые правки.

### Шаг 3. Собрать обработку в одном месте

- [ ] Перенести подробные данные запросов и журнал в «Сведения → Обработка».
- [ ] Убрать дублирующее название «Подробности обработки» и пустой legacy-блок.
- [ ] Не удалять сохранённые переводы и исторические сведения обработки.
- [ ] Оставить краткий прогресс, остановку, ошибки, предупреждения и восстановление
  вне скрываемой вкладки.
- [ ] Добавить переход «Открыть журнал» возле ошибки с открытием нужного раздела.

### Шаг 4. Убрать вспомогательные промпты из рабочей области

- [ ] Перенести форму в «Сведения → Дополнительно → Инструкции модели».
- [ ] Оставить промпты нового конспекта и статьи в соответствующих формах запуска:
  это не вспомогательные промпты.
- [ ] Сохранить черновики, сохранение настроек и применение к следующим запросам.

### Шаг 5. Очистить пункт меню и проверить целиком

- [ ] Удалить пункт «Технические сведения и параметры» после переноса его областей.
- [ ] Обработать старое сохранённое `technical` без потери остальных preferences.
- [ ] Обновить MASTER, workspace override, CONTRACTS и затронутые руководства;
  добавить существенные изменения в историю разработки.
- [ ] Проверить один плеер и один редактор, сохранение Undo/черновика при смене
  вкладки, независимый выбор версий и переходы по таймкодам.
- [ ] Выполнить профильные проверки и `python scripts/check-fast.py`.
- [ ] Проверить UI на широком и узком окне, с клавиатурой и масштабированием.
  Браузерная проверка не является проверкой установленного WebView2.

Каждый шаг — отдельное небольшое изменение с проверками и локальным коммитом.
Общую миграцию UI, изменение обработки речи, установку моделей и выпуск версии
этот план не включает.
