# Video Descriptor — нативный прототип Windows

Пользовательский сценарий: открыть приложение → добавить видео/аудио → проверить
расшифровку и границы реплик → скачать SRT/VTT/TXT. Не нужен devcontainer, Docker
или WSL. Требуются установленный OpenVINO runtime, совместимое устройство и Whisper small.
Это проверочная сборка. Безмодельный запуск и установка проверены в Windows Sandbox;
полная установка с моделями на отдельной чистой VM ещё не проверена.

Обновление 0.4: добавлены ZIP с собственным Python runtime и Windows installer;
веса остаются внешними. [Сборка, установка, CI и фактические проверки](../docs/windows-release.md).
Инструкции venv ниже относятся к работе из исходников, а не к запуску готового ZIP.

В текущих исходниках появился мастер **«Настроить модель»**: выберите существующую
папку Whisper small FP16 OpenVINO, нажмите **«Подключить модель»**, затем
**«Подготовить распознавание»**. Можно сначала проверить файлы отдельно.
Мастер проверяет комплект и SHA256 проверенного профиля, сохраняет путь в локальных
настройках и применяет его к новым заданиям. Веса остаются на месте; автоматических
загрузок нет. Во время обработки или подготовки модели смена запрещена.
Пока поддерживается именно проверенная версия small FP16, а не произвольный экспорт.
Этот мастер ещё не входит в ранее собранные ZIP/EXE 0.4.

Рядом доступна настройка **«Перевод через Ollama»**: обновите список установленных
моделей и нажмите **«Подключить перевод»**. Проверяется поддержка генерации текста;
embedding-модели и отсутствующие веса отклоняются. Выбор сохраняется в общих с
расширенным редактором настройках перевода. Существующие прочие настройки/ключи
сохраняются. Для конспекта модель выбирается отдельно в конструкторе.
Статус «Модель установлена» подтверждает обнаружение весов, а не успешный перевод.
Ollama нужно запустить отдельно; её установка и скачивание моделей ещё не автоматизированы.

## На этой машине

Двойной щелчок по `Open-App.cmd` в этой папке либо по ярлыку **Video Descriptor**
на рабочем столе, если он создан. Браузер откроется сам. Повторное открытие
использует работающий экземпляр; вручную вводить адрес не нужно.

В PowerShell из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '.\windows-app\Start-App.ps1'
```

Если модель не загружена — кнопка **«Подготовить распознавание»** запускает
существующий `windows-benchmark/whisper_npu_server.py`, не меняя файлы, окружение
и модель. Загрузка может занять около минуты или дольше. Второй worker при
занятом порте не запускается. Ошибки сохраняются в `runtime/logs/npu.log`.

Другие команды:

```powershell
# Проверки без загрузки модели и без запуска обработки
powershell -NoProfile -ExecutionPolicy Bypass -File '.\windows-app\Start-App.ps1' -Doctor
# Запуск без открытия вкладки
powershell -NoProfile -ExecutionPolicy Bypass -File '.\windows-app\Start-App.ps1' -NoBrowser
# Запустить имеющийся NPU worker вместе с приложением
powershell -NoProfile -ExecutionPolicy Bypass -File '.\windows-app\Start-App.ps1' -StartNpu
# Штатная остановка UI (во время работы очереди отказ); NPU/Ollama не останавливаются
powershell -NoProfile -ExecutionPolicy Bypass -File '.\windows-app\Start-App.ps1' -Stop
```

Можно просто закрыть вкладку: обработка продолжится. Для завершения UI использовать
кнопку «Завершить приложение». Рабочий процесс очереди выходит после простоя;
внешние NPU/Ollama могут оставаться загруженными для повторного использования.

## Подготовка на другой машине

Нужны Windows x64, Python 3.11+ (проверен 3.12.10), подходящий драйвер Intel NPU,
официальный Whisper small FP16 OpenVINO IR и работоспособное отдельное NPU-окружение.
Чистая Windows-установка пока не проверена. NPU-модель имеет размер около 493 MB;
её скачивание не входит в installer прототипа.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '.\windows-app\Install-App.ps1' -CreateShortcut
```

Этот скрипт создаёт `.venv-windows` в корне и устанавливает версии из
`requirements-lock.txt`, включая FFmpeg binary через imageio-ffmpeg
(Windows wheel около 31.2 MB, распакованный binary больше). Вместе с ML-библиотеками
объём зависимостей больше; заранее иметь минимум 2 GB свободного места для окружения
и дополнительный запас под видео/PCM WAV (около 115 MB в час для 16-kHz mono PCM16).
Существующая `.venv-npu` не используется как окружение приложения и не изменяется.
FFprobe заменяется PyAV, если отдельного ffprobe нет. Tesseract нужен для OCR,
в режиме расшифровки он не требуется. В lock включены и инструменты разработчика,
это ещё не оптимизированный размер публичного дистрибутива.

Драйверы, Docker, WSL, системный Python и AI-модели автоматически не устанавливаются.
Их отдельная установка/скачивание требует предварительного согласования. Если NPU уже
работает по адресу `127.0.0.1:8766`, прототип подключается к нему и проверяет профиль.

Для своего расположения создать `config.local.json`, например:

```json
{
  "npu_worker_directory": "D:/AI/windows-benchmark",
  "ollama_model": "qwen3.5:9b"
}
```

Путь `workspace` разрешён только внутри `windows-app/runtime/`.
HTTP-сервисы в этом прототипе должны быть loopback. UI слушает `127.0.0.1:8780`.

## Данные, модели и восстановление

- Код/конфигурация — `windows-app/`; локальные настройки — `config.local.json`.
- Новые исходники — `runtime/workspace/data/uploads/<job-id>/`.
- Новые результаты, очередь, VAD и HTTP-checkpoint — `runtime/workspace/output/`.
- Логи — `runtime/logs/`, `runtime/workspace/output/jobs/<job-id>/run.log`.
- Модели — внешние каталоги `windows-benchmark` и Ollama; дубликаты не создаются.
- Исторические `data/`, `output/`, `.env*` основного проекта не импортируются
  и не запускаются автоматически; для них ещё нужна миграция Linux-путей.

Кнопка продолжения повторяет незавершённую часть, готовые блоки берёт из кэша.
Язык и engine identity входят в проверку совместимости. При изменении языка/модели
нужна новая версия, а не смешивание результатов. После аварийного завершения
очередь при следующем запуске worker помечает старое `running` как ошибку;
пользователь может повторить задание. Само открытие UI не запускает старую очередь.

Текст/тайминги редактируются отдельно в `transcript-edits.json`; исходный `speech.json`
остаётся прежним. Revision не даёт перезаписать более свежую правку из другой вкладки.
Идентификаторы сегментов сохраняются при правке. При разделении создаётся отдельный ID
второй части. SRT использует порядковые номера, стабильные ID остаются в JSON/VTT.
Точность сегментных меток нельзя выдавать за точность отдельных слов.

## Возможности и границы

Проверен локальный режим Whisper small NPU/Intel GPU/CPU без определения говорящих, VAD перед
распознаванием, выбор auto/RU/UK/EN в запросе, очередь, воспроизведение, правка, SRT/VTT/TXT.
Полноценные EN/UK/mixed-language оценки качества ещё не выполнены.
Тишина даёт пустой результат; отсутствие речи по VAD — автоматическое решение,
которое тоже может ошибаться. `end=-1` не превращается в выдуманную границу.
Невалидный успешный JSON сохраняется в `invalid-response.json`; если старый worker
вернул только HTTP 500 без сырых chunks, клиент не может восстановить эти chunks.

Перевод/конспект доступны через ссылку в расширенный существующий редактор и требуют
работающей Ollama/выбранной модели либо явно настроенного облачного провайдера.
В этом запуске Ollama не была доступна; эти стадии не прошли новое end-to-end испытание.
Windows XPU/pyannote и desktop-оболочка не входят в проверенный первый режим.
Облачные ключи из старого проекта в sandbox автоматически не переносятся;
backend запускается с offline-флагами для Hugging Face, без скачивания моделей.

## Обновление, откат и удаление

Автоматического updater пока нет. Перед сменой кода дождаться пустой очереди,
завершить UI и сохранить `runtime/workspace` и `config.local.json`. Обновление кода
и зависимостей выполнять отдельно от NPU-окружения; прежний коммит/lock сохраняются в Git.
Несовместимые схемы результатов нельзя молча менять: требуется отдельная migration.

Откат прототипа: завершить UI и пользоваться сохранённым WSL-проектом.
Удаление самого приложения/ярлыка не должно удалять `runtime/workspace`, внешние
модели или старые `data/output`. Скрипт удаления намеренно не выполняет очистку данных.

```powershell

.\.venv-windows\Scripts\python.exe -X utf8 .\windows-app\verify_runtime.py '.\data\Фригг.mp4'
```

## Устройство распознавания (0.3)

В новой записи выберите **Авто · NPU → GPU → CPU**, NPU, GPU либо CPU.
Настройка сохраняется; изменение касается только новых заданий. Если модель ещё
не готова, нажмите «Подготовить распознавание». Проверяется профиль модели/runtime,
а не только наличие адаптера. GPU здесь означает Intel OpenVINO; другие GPU не проверены.
Ручной режим выдаёт ошибку при отказе. Auto переходит к следующему доступному backend,
сохраняя готовые речевые фрагменты и историю переходов.

CPU/GPU используют новый `whisper_worker.py`; существующий NPU сервис не меняется.
Для независимой установки CPU/GPU можно задать в `config.local.json`:
`openvino_python` — путь к Python с OpenVINO/GenAI и зависимостями worker;
`whisper_model_directory` — путь к локальной FP16 IR Whisper small.
Пустые значения используют уже имеющиеся benchmark Python/модель на этой машине.
Это ещё не установка на чистой Windows. Автоматической загрузки весов нет.

Журнал действий доступен в панели «Готовность → История действий»;
полный файл — `runtime/logs/events.jsonl`. Логи CPU/GPU — `runtime/backends/`.
Текст речи и ключи в журнал действий не включаются. Для явной аппаратной проверки:

```powershell
.\.venv-windows\Scripts\python.exe -X utf8 windows-app/verify_devices.py path/to/short.mp4
```

Команда добавляет четыре задания и временно меняет настройку, восстанавливая её в конце.
Запускать на свободной очереди. [Отчёт](../docs/verification-devices.md).
