# Граница ближайшего выпуска — пригодная установка и использование

Дата: 17.10.2026. Последнее уточнение владельца имеет приоритет над прежними
ADR о всеобщей нативности или обязательном переносе всего в Docker Compose.

Цель: пользователь устанавливает приложение, настраивает необходимое через мастер
и получает результат из видео. Выбор runtime — средство снизить сложность поставки.
Проверенные NPU/локальный UI/launcher остаются. Docker/Compose допустим за тем же
фасадом для тяжёлых/неудобных зависимостей, если его готовность реально проверена.
Новая desktop-оболочка и переписывание всех работающих стадий не являются обязательной
работой перед выпуском. Наличие Docker не считать само по себе решением совместимости GPU/NPU.

## Уже подтверждено

- Native ASR на NPU/Intel GPU/CPU, ручной выбор и Auto; локальные checkpoints и история.
- Queue, VAD, правка текста/границ, SRT/VTT/TXT; исходные материалы и результаты сохраняются.
- В исходниках: мастер подключения существующей Whisper small FP16 с проверкой SHA256,
  сохранением пути и применением без перезапуска; импорт проверен через UI на настоящих весах.
- В исходниках: выбор установленной модели Ollama через UI с проверкой completion;
  Qwen подключена, выбор совместим с настройками расширенного редактора.
- В 0.6: запуск перевода/конспекта кнопками на основной странице, отдельная версия и
  закреплённая модель, очередь/продолжение/история; реальный UI-прогон на хосте прошёл.
- ZIP 0.6: реальный 20 s MP4 → CPU → native/postprocess → конспект/перевод → русский SRT
  прошёл без ручного запуска стадий CLI; EXE собран, его отдельный lifecycle ещё не повторён.
- В ZIP 0.5: реальный новый 20 s MP4 → CPU ASR → отдельная версия конспекта Qwen →
  перевод → русский SRT; полнота перевода/notes/chapters/report проверена.
  Управление прогоном выполнено проверочным скриптом через API и bundled CLI;
  это не подтверждение единой кнопки всех этапов в простом UI.
- ZIP с Python/OpenVINO/FFmpeg и per-user installer; повторяемый ZIP и hash manifests.
- ZIP/installer 0.5 на хосте: запуск без системного Python в PATH, install/reinstall,
  отказ занятого update, upgrade fixture 0.5.1, uninstall с сохранением данных/настроек.
- Настоящий Windows Sandbox без системного Python, без сети/моделей: запуск, 4387 hashes,
  install/reinstall, отказ занятого update, uninstall с сохранением данных; гостевой UI открыт.
  Это результат 0.4. Новый Sandbox-прогон 0.5 остановлен Application Control на DLL
  psutil/charset_normalizer до проверки installer; защита не менялась. См.
  verification-sandbox-0.5.json; успешный старый прогон не переносится на новую сборку.
- CI workflow написан, но на GitHub не запускался. Самостоятельная минимальная VM
  и аппаратное ASR в Sandbox не объявляются пройденными.

## Четыре оставшихся блока

1. **Первоначальная настройка.** Выбор расположения моделей/данных в UI, обнаружение
   имеющихся моделей, предложение нужных загрузок с размером, checksum и явным согласием.
   После установки не требовать редактировать config JSON или работать в терминале.
2. **Управление компонентами через один фасад.** Запуск, readiness, остановка только
   собственных процессов/сервисов, ошибки и логи. Whisper, Ollama и при необходимости
   Compose должны выглядеть как возможности приложения. Не останавливать чужие сервисы.
3. **Полный пользовательский путь.** Реально проверить установленные перевод, конспект
   и при необходимости OCR на одном контрольном видео; не выдавать наличие исходников
   этих стадий за готовую Windows-поставку. Диаризацию показывать по фактической поддержке.
4. **Итоговая приёмка поставки.** На чистой гостевой системе пройти установку с моделями
   и получение результата; отдельно реальный NPU/GPU host, CPU fallback, update/uninstall,
   пути с пробелами/кириллицей, сбои загрузки/сети. Затем проверить CI artifacts.

Главный пробел сейчас — setup моделей/сервисов и подтверждение полного сценария,
а не создание ещё одного формата установщика. Sandbox без моделей доказал запуск
приложения, но не завершённость продукта. Процент готовности и обещание срока из этой
проверки не выводятся. Мастера существующего Whisper и установленной Ollama реализованы
в новой ZIP/EXE 0.5. Контрольный speech-only конвейер из ZIP прошёл на хосте.
Следующие шаги: решить поставку native DLL для Application Control без отключения
защиты, повторить гостевую приёмку и завершить помощь в установке/запуске сервисов.
Автоматическая установка сервисов и загрузка больших весов ещё не реализованы.
