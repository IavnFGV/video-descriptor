# Стратегии отбора кадров

Задача — сохранить смену слайдов и видимые изменения, не отправляя модели
каждую секунду видео. Отбор не распознаёт смысл: OCR читает выбранные изображения,
а затем модель сама решает, какие из них нужно визуально рассмотреть.

## Доступные стратегии

| Стратегия | Что делает | Когда выбирать |
|---|---|---|
| `scene` (по умолчанию) | Штатный FFmpeg: проверка раз в секунду, изменения плюс контрольные кадры | Лекции со слайдами, квизами и переменной активностью |
| `interval` | Снимок через фиксированный интервал, прежняя реализация через OpenCV | Для сравнения, предсказуемого числа кадров или очень спокойной записи |

Один файл:

```bash
python -m video_descriptor "data/лекция.mp4" --model qwen3.5:9b --frame-strategy scene
python -m video_descriptor "data/лекция.mp4" --model qwen3.5:9b --frame-strategy interval --frame-interval 15
```

Все видео из `data/`, вместе с переводом:

```bash
python scripts/process_videos.py --frame-strategy scene
```

## Параметры настройки

| Параметр | По умолчанию | Эффект |
|---|---:|---|
| `--scan-interval` | 1 сек | Интервал проверки в `scene`; 0.5 проверяет дважды в секунду |
| `--scene-threshold` | 0.01 | Порог показателя FFmpeg `scene`, от 0 до 1; меньше — чувствительнее и больше кадров |
| `--max-frame-gap` | 60 сек | Контрольный кадр, если после предыдущего сохранённого прошло столько времени |
| `--frame-interval` | 15 сек | Используется только стратегией `interval` |

Те же параметры принимает `scripts/process_videos.py`. Значения — стартовые
настройки, а не универсальный оптимум. Порог `scene` не является процентом
изменённых пикселей и не означает уверенность модели.

Фильтр по умолчанию:

```text
fps=1/1,select='isnan(prev_selected_t)+gt(scene,0.01)+gte(t-prev_selected_t,60)'
```

Первый кадр сохраняется всегда. Затем сохраняется кадр с изменением выше порога
или контрольный кадр. Частота проверки ограничивает максимальную частоту отбора.
Условие контрольного интервала отсчитывается от последнего выбранного кадра,
а не от начала очередной календарной минуты.

Используются штатные фильтры [FFmpeg fps](https://ffmpeg.org/ffmpeg-filters.html#fps)
и [select](https://ffmpeg.org/ffmpeg-filters.html#select_002c-aselect).
`metadata` сохраняет реальные временные метки выбранных кадров и `lavfi.scene_score`.
Кадры выводятся с переменным интервалом (`-fps_mode vfr`), без искусственных дублей.
FFmpeg декодирует видео для проверки; это тоже занимает время. OCR работает только
для выбранных кадров. Модель на этапе отбора не вызывается.

## Как подобрать настройки

Сначала проверить короткий знакомый фрагмент с новым слайдом и раскрытием ответа:

```bash
python -m video_descriptor "data/лекция.mp4" --start 1900 --duration 180 --skip-notes --frame-strategy scene
```

Открыть картинки в `frames/` и файл `frame-selection.json`. В нём сохранены
точный фильтр, параметры, ID кадров, время, показатель изменения и причина:
`initial`, `change` или `heartbeat`. `frames.json` содержит OCR и исходные таймкоды.

- Если нужное выделение пропущено — попробовать порог `0.005`. Если событие короче
  секунды — также уменьшить `--scan-interval` до `0.5`.
- Если много кадров из-за движения преподавателя или интерфейса — попробовать
  порог `0.02`; проверить, не потерялось ли выделение ответа.
- Если между полезными снимками большие промежутки — уменьшить
  `--max-frame-gap`, например до `30`.

Пример настройки всех файлов:

```bash
python scripts/process_videos.py --scene-threshold 0.005 --scan-interval 0.5 --max-frame-gap 30
```

Это примеры подбора, а не обещание ускорения или полноты. Показатель `scene`
оценивает весь экран: небольшая рамка может быть пропущена, движение камеры —
дать лишние кадры. Дубли слайда пока не удаляются через сравнение OCR; область
слайда автоматически не выделяется. Контрольные снимки снижают риск пропусков,
но не восстанавливают краткое событие между проверками.

Проверка на текущей записи: фрагмент 1900–2080 секунд с квизом, настройки по
умолчанию. Выбрано 5 кадров: 1900, 1960, 1967, 2027, 2059 секунд. OCR подтвердил
раскрытие правильного ответа на 1967 и следующий вопрос на 2059. Готовый Whisper
переиспользован из прежней папки. Результат: `output/2026-10-05 11-04-45-fb6e94f937/`.
Это проверка отбора и OCR, без повторного запроса модели и без замера преимущества
в скорости: одновременно шла другая обработка.

## Кэш и возобновление

Стратегия и её параметры входят в идентификатор результата. Старые отчёты и
картинки сохраняются в прежней папке. Для новой стратегии используется новая
папка с отдельными кадрами, OCR и анализом модели.

Аудио, готовая расшифровка, её промежуточная контрольная точка и готовый перевод
переиспользуются из совместимой папки. Проверяются путь, размер и время изменения
видео, начало/длина фрагмента, модель Whisper и язык. При переносе контрольной
точки меняется только путь к тому же WAV; остальные проверки Whisper сохраняются.
Это не заставляет заново распознавать речь только из-за смены кадров.

Уже работающий процесс продолжает старую стратегию. Новая применяется при новом
запуске; второй файл в пакетной очереди запускается отдельным процессом.

## Где менять или добавлять стратегию

- `video_descriptor/frames.py`: построение штатного FFmpeg-фильтра, извлечение
  выбранных JPEG и их метаданных, OCR.
- `video_descriptor/media.py`, `extract_frames`: переключение стратегии;
  прежняя `interval` остаётся доступной.
- `video_descriptor/__main__.py`: параметры CLI, настройки в идентификаторе кэша
  и метриках. При изменении алгоритма увеличить `frame_selection.version`.
- `scripts/process_videos.py`: передача этих параметров при пакетном запуске.
- `video_descriptor/cache.py`: независимое переиспользование речи.

Контракт любой новой стратегии: вернуть список `Source` с уникальными ID,
абсолютными `start/end`, OCR-текстом и относительным путём к картинке. Время
сохранённого кадра нельзя вычислять как его номер × фиксированный интервал.
`end` — следующий выбранный кадр или конец фрагмента; это приблизительный период
наблюдения экрана, а не доказанная граница темы. Проверить смену слайда, неподвижный
экран с контрольными кадрами, абсолютные таймкоды и сохранение кэша Whisper.
