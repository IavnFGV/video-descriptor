# Локальные Windows-сборки и очистка

12.11.2026: единственный текущий профиль — стандартный установщик без встроенных
Whisper/community-1. Domestic/cached удалены. Датированные записи ниже о полном
автономном пакете и его замерах — исторические, не инструкции текущей сборки.

Локальная очередь собирает installer в фоне, но не запускает установку приложения.
Настроенный post-merge также может перезапустить отдельный source preview.
Удалённый полный offline-профиль описан только в исторических замерах в конце
страницы и в [истории](development/history.md).

**Известное ограничение текущей Windows-реализации:** `local_build.py` вызывает
`check-fast.py` в изолированном checkout, используя Python из общей конфигурации.
Guard Fast требует `.venv` именно этого checkout. Внешний interpreter, включая
прежний `.venv-windows`, не удовлетворяет этой проверке, и этап `checks` завершается
ошибкой до упаковки. Параметры ниже существуют, но успешный сквозной Windows build
с текущим guard не подтверждён; требуется отдельное исправление кода, не обход guard.


По умолчанию `Build-Local.ps1` и локальный post-merge main собирают стандартный
установщик. Результат: `dist/local/<версия>/`. Внутренний ZIP/staging сохраняется
для сборки и smoke-проверки; это не отдельная редакция приложения.

Флаги `-Domestic`, `--domestic`, `--cached` и `--domestic-inputs` больше не поддерживаются.
Старая Domestic/cached-заявка явно останавливает очередь с ошибкой и сохраняется:
её нужно отменить вручную перед продолжением. Сохранённые пакеты/модели не удаляются.

Работает без GitHub runner, установки служб и изменения рабочего приложения.
Нужны уже установленное dev Python-окружение, Node, .NET, PowerShell и Inno Setup.
Зависимости/модели автоматически не устанавливаются. Закреплённые build inputs
при отсутствии могут скачиваться существующим builder; большие AI-веса исключены.

## Обычная работа

Откройте `dist/local/build-status.html` в браузере: страница обновляется каждые
3 секунды, показывает текущий этап/ошибку и даёт ссылки на журнал и последнюю
готовую версию. Сервер и терминал для просмотра не нужны. При следующей сборке
тот же файл обновляется автоматически. До первого запуска файла может не быть.

Из корня проекта:

```powershell
.\scripts\Build-Local.ps1              # собрать текущий commit HEAD
.\scripts\Build-Local.ps1 -Background  # та же очередь в скрытом фоновом процессе
.\scripts\Build-Local.ps1 -Ref main    # собрать точный текущий локальный main
.\scripts\Build-Local.ps1 -Status      # состояние, этап, очередь, журнал, результат
```

Скрипт собирает **закоммиченные** файлы. Незакоммиченные изменения не входят.
Отдельный detached worktree не переключает вашу ветку и не затрагивает пользовательские
настройки, очередь, видео, модели или установленную программу.

Последовательность: checkout точного SHA → desktop SDK → `scripts/check-fast.py` →
`build_release.py` (ZIP+EXE) → `verify_release.py` → SHA256 + provenance.

Ошибка прекращает сборку этого коммита и сохраняет этап/журнал; следующие запросы
очереди продолжают выполняться. OS-lock снимается при завершении/падении процесса.
Повтор готового SHA сверяет наличие и хеши ZIP/EXE и переиспользует результат.
Повтор неудачного или повреждённого результата создаёт новую попытку.

ZIP/EXE стандартной сборки: `dist/local/<версия>/`.
Технические попытки, `source/` (detached worktree) и `build.log` находятся в
`<git-common-dir>/local-build/runs/`. При новой сборке той же версии папка
содержит последний успешно проверенный результат; SHA сохраняется в provenance.
`provenance.json` содержит полный SHA, версию, пути, размеры и хеши.
Версия берётся из `windows-app/release-inputs.json`, автоматически не увеличивается.

Это portable smoke на текущей Windows, а не проверка жизненного цикла установщика. Установки в рабочую папку пользователя, публикации, остановки рабочего приложения, скачивания моделей или
проверки install/upgrade/uninstall на чистой VM здесь нет.

## Однократное подключение на компьютере

Конфигурация хранится локально в Git common directory: `local-build/config.json`.
В репозиторий абсолютные пути этой машины не попадают. Пример настройки:

```powershell
python scripts/local_build.py configure `
  --python 'D:\projects\video-descriptor\.venv\Scripts\python.exe' `
  --cache 'E:\LocalAI\video desriptor\windows-app\runtime\build-cache' `
  --iscc 'E:\LocalAI\video desriptor\windows-app\runtime\build-cache\inno-6.7.3\ISCC.exe' `
  --desktop-sdk 'D:\projects\video-descriptor\windows-app\runtime\desktop-sdk'
python scripts/local_build.py install-hook
```

`install-hook` устанавливает локальный `post-merge`. После успешного merge или
`git pull` в **локальном main** он запускает очередь в скрытом процессе и сразу
возвращает управление Git. Сторонний существующий hook не перезаписывается;
его владелец должен самостоятельно добавить вызов `Build-Local.ps1 -Background`.
Повторная установка нашего hook допустима. Другие ветки автоматически не собираются.
Прямой commit/rebase/reset/checkout не является post-merge: используйте команду вручную.

Merge на GitHub требует локального `git pull`, чтобы hook сработал здесь.
Фоновый fetch/pull, планировщик и постоянная служба не устанавливаются.
Пока изменения этих скриптов не попали в main, его старый checkout не содержит
команду запуска; hook в таком checkout ничего не делает.

Пример `configure` показывает синтаксис, не готовую конфигурацию другой машины.
Подставьте существующие пути; даже корректный внешний dev Python не устраняет
описанный выше конфликт с guard изолированного checkout. Не устанавливайте hook
до решения этого ограничения, если ожидаете успешную автоматическую сборку.

Состояние, запросы очереди, результаты и lock находятся в
`<git-common-dir>/local-build/`. Отдельные launcher-логи не создаются. Ошибки самой сборки находятся в `log` из `-Status`; при ошибке запуска до первого этапа повторите команду без `-Background`, чтобы увидеть сообщение в терминале.
Отключение автозапуска: удалить только наш `<git-hooks>/post-merge` с маркером
`video-descriptor-local-build`. Это не удаляет результаты и не отменяет уже начатую сборку.

## Очистка

```powershell
.\scripts\Clean-Local.ps1                     # только список и объём
.\scripts\Clean-Local.ps1 -Apply              # удалить рассчитанный список
.\scripts\Clean-Local.ps1 -Keep 5 -Days 14    # более длительное хранение
```

По умолчанию сохраняются три последние **версии** ZIP/EXE в `dist`, `dist-clean` и `dist/local`. Для старого SHA-формата
совместимость очистки сохраняет три последние автоматические сборки. Удаляются только узнаваемые имена пакетов.
Незнакомые файлы в этих каталогах и отчёты проверки сохраняются.
Незакоммиченные корневые `*.log` и временные `payload-*`/`vcrt-*` в явно
настроенном build cache удаляются лишь старше семи дней.

Никогда не выбираются модели, видео, `.env`, venv, исходники, tracked-логи,
скачанные архивы зависимостей, wheels, Inno Setup и desktop SDK.
История исходных worktrees автоматически не удаляется.
Символические ссылки/junctions и пути за пределами выбранных output/cache roots
отклоняются; перед удалением повторно проверяются абсолютные пути и изменения файлов.
Очистка отказывается работать при активной локальной сборке, проверке или smoke.
Каждый запуск сохраняет JSON-отчёт в Git common directory; preview ничего не удаляет.

## Проверки реализации

`tests/test_local_build.py`: очередь новых SHA во время сборки, OS-lock после ошибки,
остановка при провале checks, отказ переиспользовать повреждённый EXE/ZIP,
сохранение существующего hook, реальный post-merge в временном Windows-репозитории,
retention и защита файлов/границ очистки. Полный сквозной запуск выполняется
командой `Build-Local.ps1` на закоммиченном SHA.

Распаковка CAB использует только `%SystemRoot%/System32/expand.exe`: в окружении
Git hook одноимённая GNU-утилита может находиться первой в PATH. При ошибке
журнал содержит stdout/stderr системного распаковщика.

Cleanup после очереди: известные untracked root `*.log` и старые launcher-логи удаляются без семидневной задержки (CLI `--days` по умолчанию 0). Временные checkout/artifacts и orphan scratch удаляются под OS-lock после завершения проверок. Основные журналы текущего статуса и последнего успеха сохраняются; прочие build.log удаляются. Один cleanup.json заменяет накопление timestamp-отчётов. Wheels, инструменты, исходные модели, .env и пользовательские данные не являются временными файлами.

check-fast не создаёт pytest/ruff cache и Python bytecode; сборочные дочерние процессы также запускаются с PYTHONDONTWRITEBYTECODE=1.

`TEMP/TMP/TMPDIR` меняются только для дочерних процессов: `<cache>/temp/<run>` либо
настроенный `--temp-root`. Глобальное окружение Windows не меняется. Статус показывает
текущую операцию, длительность и последние строки `build.log`; процент/ETA не выдумываются.
`python scripts/local_build.py watch-status` обновляет страницу уже работающей очереди.

## Исторические замеры удалённого кешируемого профиля (08.11.2026)

На этом Windows-хосте 0.8.28: упаковка ZIP+EXE 14:02 (Inno 11:27), portable-smoke 8:57. Прогретый кеш 0.8.29: полный EXE 24,39 с, install/reinstall/health/uninstall проверка того же EXE 78,12 с; повторная установка без перезаписи runtime 8–10 с. Общий набор unit/static по-прежнему запускается для каждого merge (~2–3 мин), поэтому ожидаемый полный локальный цикл с готовым кешем около 4 мин. Первый прогрев/изменение runtime или installer требует расширенной первой установки и CPU inference; это не обещание одинакового времени на всех компьютерах.

Кеш компонентов хранит максимум две последние версии входов. Временные app payload, установочные копии и журналы удаляются; опубликован только полный EXE, проверки/хеши и provenance. `/VDLocalTest=1` используется только verifier для отдельного AppId; обычный запуск того же EXE сохраняет исходный production AppId и устанавливает приложение как прежде.

## Проверка правок без установщика

После merge main открывается локальная версия из этого checkout; полный EXE параллельно собирается в фоне. Настройка машины хранится в общем для worktree `.git/local-dev/config.json`: `python` — существующий dev interpreter, `port` — свободный локальный порт (здесь 8781), `development: true`, `records_directory` — папка рабочих записей. Остальные ключи повторяют `windows-app/config.example.json`. Не коммитить локальные пути/настройки.

`./scripts/Run-Dev.ps1 -Open` открывает локальное приложение; `-Restart -Open` подхватывает изменения Python, `-Stop` останавливает только preview. Для HTML/CSS/JS достаточно обновить страницу (после CSS-правок выполнить `python scripts/build-ui-css.py`). Настройки, записи и результаты общие с установленной версией; revision и worker locks сохраняются. Перезапуск preview меняет только HTTP-процесс: независимый worker, NPU-сервис и общая очередь продолжают работу. Подготовка компонентов и перенос хранилища по-прежнему блокируют остановку. Точный открытый коммит есть на странице и в `.git/local-dev/status.json`. Файлы и зависимости не копируются в новый установщик для каждого ручного просмотра.
