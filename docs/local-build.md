Очередь показывает ожидающие коммиты без активного запроса. Страница обновляется во время длительных команд; процент и ETA не выдумываются. Inno Setup запускается с обычным подробным выводом вместо тихого режима. Команда `python scripts/local_build.py watch-status` обновляет страницу уже запущенного worker без изменения его состояния.


Домашний профиль: `Build-Local.ps1 -Domestic`; обновлённый post-merge hook main
передаёт `-Domestic` по умолчанию. Требуется локальный `--domestic-inputs` в
конфигурации. В этом профиле модели и CPU диаризация включены в пакет;
результаты находятся в `dist/local/domestic/<версия>/`.
См. [состав и подготовку](domestic-installer.md). Ограничения ниже о невключённых
моделях относятся к стандартной сборке без `-Domestic`.

Работает без GitHub runner, установки служб и изменения рабочего приложения.
Нужны уже установленное dev Python-окружение, Node, .NET, PowerShell и Inno Setup.
Зависимости/модели автоматически не устанавливаются. Закреплённые build inputs
при отсутствии могут скачиваться существующим builder; большие AI-веса исключены.

## Обычная работа

Откройте `dist/local/build-status.html` в браузере: страница обновляется каждые
3 секунды, показывает текущий этап/ошибку и даёт ссылки на журнал и последнюю
готовую версию. Сервер и терминал для просмотра не нужны. При следующей сборке
тот же файл обновляется автоматически. До первого запуска файла может не быть.

Из корня проекта:

```powershell
.\scripts\Build-Local.ps1              # собрать текущий commit HEAD
.\scripts\Build-Local.ps1 -Background  # та же очередь в скрытом фоновом процессе
.\scripts\Build-Local.ps1 -Ref main    # собрать точный текущий локальный main
.\scripts\Build-Local.ps1 -Status      # состояние, этап, очередь, журнал, результат
```

Скрипт собирает **закоммиченные** файлы. Незакоммиченные изменения не входят.
Отдельный detached worktree не переключает вашу ветку и не затрагивает пользовательские
настройки, очередь, видео, модели или установленную программу.

Последовательность: checkout точного SHA → проверка/подготовка desktop SDK →
`scripts/check-fast.py` → существующий `build_release.py` (ZIP + EXE) →
`verify_release.py` без installer lifecycle → SHA256 + provenance.
Ошибка прекращает сборку этого коммита и сохраняет этап/журнал; следующие запросы
очереди продолжают выполняться. OS-lock снимается при завершении/падении процесса.
Повтор готового SHA сверяет наличие и хеши ZIP/EXE и переиспользует результат.
Повтор неудачного или повреждённого результата создаёт новую попытку.

Результаты по умолчанию: `dist/local/<версия>/`, например `dist/local/0.8.18/`.
Технические попытки, `source/` (detached worktree) и `build.log` находятся в
`<git-common-dir>/local-build/runs/`. При новой сборке той же версии папка
содержит последний успешно проверенный результат; SHA сохраняется в provenance.
`provenance.json` содержит полный SHA, версию, пути, размеры и хеши.
Версия берётся из `windows-app/release-inputs.json`, автоматически не увеличивается.

Это проверка portable-запуска на текущей Windows. Автоматической установки,
публикации, остановки приложения, скачивания моделей, аппаратного inference или
проверки install/upgrade/uninstall на чистой VM здесь нет.

## Однократное подключение на компьютере

Конфигурация хранится локально в Git common directory: `local-build/config.json`.
В репозиторий абсолютные пути этой машины не попадают. Пример настройки:

```powershell
python scripts/local_build.py configure `
  --python 'E:\LocalAI\video desriptor\.venv-windows\Scripts\python.exe' `
  --cache 'E:\LocalAI\video desriptor\windows-app\runtime\build-cache' `
  --iscc 'E:\LocalAI\video desriptor\windows-app\runtime\build-cache\inno-6.7.3\ISCC.exe' `
  --desktop-sdk 'D:\projects\video-descriptor\windows-app\runtime\desktop-sdk'
python scripts/local_build.py install-hook
```

`install-hook` устанавливает локальный `post-merge`. После успешного merge или
`git pull` в **локальном main** он запускает очередь в скрытом процессе и сразу
возвращает управление Git. Сторонний существующий hook не перезаписывается;
его владелец должен самостоятельно добавить вызов `Build-Local.ps1 -Background`.
Повторная установка нашего hook допустима. Другие ветки автоматически не собираются.
Прямой commit/rebase/reset/checkout не является post-merge: используйте команду вручную.

Merge на GitHub требует локального `git pull`, чтобы hook сработал здесь.
Фоновый fetch/pull, планировщик и постоянная служба не устанавливаются.
Пока изменения этих скриптов не попали в main, его старый checkout не содержит
команду запуска; hook в таком checkout ничего не делает.

Состояние, запросы очереди, результаты, lock и launcher-логи находятся в
`<git-common-dir>/local-build/`. Ошибки запуска до первого build stage ищите в
`launcher-*.error.log`; все ошибки самой сборки — в пути `log` из `-Status`.
Отключение автозапуска: удалить только наш `<git-hooks>/post-merge` с маркером
`video-descriptor-local-build`. Это не удаляет результаты и не отменяет уже начатую сборку.

## Очистка

```powershell
.\scripts\Clean-Local.ps1                     # только список и объём
.\scripts\Clean-Local.ps1 -Apply              # удалить рассчитанный список
.\scripts\Clean-Local.ps1 -Keep 5 -Days 14    # более длительное хранение
```

По умолчанию сохраняются три последние **версии** ZIP/EXE в `dist`, `dist-clean` и `dist/local`. Для старого SHA-формата
совместимость очистки сохраняет три последние автоматические сборки. Удаляются только узнаваемые имена пакетов.
Незнакомые файлы в этих каталогах и отчёты проверки сохраняются.
Незакоммиченные корневые `*.log` и временные `payload-*`/`vcrt-*` в явно
настроенном build cache удаляются лишь старше семи дней.

Никогда не выбираются модели, видео, `.env`, venv, исходники, tracked-логи,
скачанные архивы зависимостей, wheels, Inno Setup и desktop SDK.
История исходных worktrees автоматически не удаляется.
Символические ссылки/junctions и пути за пределами выбранных output/cache roots
отклоняются; перед удалением повторно проверяются абсолютные пути и изменения файлов.
Очистка отказывается работать при активной локальной сборке, проверке или smoke.
Каждый запуск сохраняет JSON-отчёт в Git common directory; preview ничего не удаляет.

## Проверки реализации

`tests/test_local_build.py`: очередь новых SHA во время сборки, OS-lock после ошибки,
остановка при провале checks, отказ переиспользовать повреждённый EXE/ZIP,
сохранение существующего hook, реальный post-merge в временном Windows-репозитории,
retention и защита файлов/границ очистки. Полный сквозной запуск выполняется
командой `Build-Local.ps1` на закоммиченном SHA.

Распаковка CAB использует только `%SystemRoot%/System32/expand.exe`: в окружении
Git hook одноимённая GNU-утилита может находиться первой в PATH. При ошибке
журнал содержит stdout/stderr системного распаковщика.
