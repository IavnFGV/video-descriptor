# Группировка материала для запросов к модели

Кадры извлекаются отдельно от группировки конспекта. FFmpeg сохраняет изменения
экрана и контрольные кадры, затем OCR читает выбранные изображения.

## Режимы

- `--chunk-strategy slides`: речь и кадры объединяются от предполагаемой смены
  слайда до следующей. При `--frame-strategy scene` это новый режим по умолчанию.
- `--chunk-strategy time`: прежнее разбиение по времени, `--chunk-seconds 180`.
  При `--frame-strategy interval` оно остаётся по умолчанию, сохраняя старый кэш.

Смена слайда определяется приближённо: сравнивается последовательность слов OCR
соседних кадров. Если сходство меньше `--slide-similarity 0.55`, начинается новый
блок. Регистр и пунктуация игнорируются. Повторные контрольные кадры и выделение
ответа без смены текста остаются вместе. При недостатке текста (менее пяти слов
на одном из кадров) используется изменение минимум 40% пикселей уменьшенного
изображения по уже имеющейся функции `frame_changes`.

Это определение смены содержимого экрана, а не доказательство смены темы.
Шум OCR, движение камеры и анимация могут давать лишние границы; похожие слайды
могут объединяться. Порог сходства можно подобрать, более высокий чувствительнее.
Один вопрос и раскрытие ответа желательно держать вместе; если OCR заметно
изменился и блоки разделились, последующее объединение квизов работает как раньше.

## Ограничение больших блоков

### Склейка коротких фрагментов

Для `slides` по умолчанию включён `--min-chunk-seconds 180`: соседние короткие
группы собираются до примерно трёх минут, даже если внутри сменилось несколько
слайдов. Модель сама выделяет разделы; в материале запроса `slide_segments`
сохраняет таймкоды исходных границ. Источники сохраняют свои ID; повторяющийся
активный кадр внутри одного запроса передаётся один раз. Короткий остаток в конце
присоединяется к предыдущей группе, если это допускают верхние ограничения.

Минимальная длительность — цель упаковки, а не требование превысить допустимый
объём. Пределы длительности и текста ниже имеют приоритет: плотная речь/OCR могут
дать блок короче 180 секунд. `--min-chunk-seconds 0` возвращает прежнюю нарезку
строго по сменам слайда. Параметр действует только для `slides`.

Для перехода незавершённого старого запуска можно добавить `--preserve-blocks N`
и `--reuse-completed-blocks`, где N — число полностью завершённых старых блоков.
Первые N групп сохраняют прежнюю нумерацию и кэш, склеивается только остаток.
Остаток получает отдельный ключ анализа; Whisper и OCR используются повторно.
При следующих перезапусках нужно повторять те же параметры, включая N.
Параметры доступны также в `scripts/process_videos.py`.

Чтобы один долгий слайд не породил чрезмерный запрос, используются пределы:

- `--max-chunk-seconds 600` — до десяти минут между началами источников;
- `--max-chunk-chars 18000` — ориентировочный объём текста источников с запасом
  на их поля. Это символы, не токены и не размер изображения.

При превышении блок делится перед очередным источником; активный кадр слайда
добавляется в продолжение. Речь не обрезается внутри распознанной реплики:
реплика, пересекающая границу, относится к блоку по времени начала.
Один очень большой источник, системный промпт, схема JSON и повторяемый кадр
могут превысить ориентировочный текстовый предел. Он не гарантирует, что модель
уложится в лимит генерации. Увеличенный повтор и пропуск ошибок остаются включены.

Лог показывает номер слайда и причину границы. `chunk-plan-<ключ>.json` содержит
время, причину, номер слайда и ID всех источников каждого запроса.
Журнал `requests/` содержит фактический запрос, выбранные картинки и ответ.

## Запуск и кэш

```bash
python scripts/process_videos.py --chunk-strategy slides
```

Продолжить старый анализ без потери готовых блоков:

```bash
python scripts/process_videos.py "data/2026-10-05 11-04-45.mp4" --frame-strategy interval --chunk-strategy time
```

Переключение стратегии группировки сохраняет Whisper и OCR, но создаёт другой
кэш анализа: границы и состав запросов изменились, результаты старых блоков
автоматически не переносятся. Те же настройки принимают CLI и пакетный скрипт.
Реализация находится в `video_descriptor/chunks.py`; отдельная стратегия времени
используется также для перевода субтитров и этим изменением не затрагивается.

## Короткий контекст лекции

По умолчанию все запросы анализа (выбор картинок, конспект, пояснение квиза,
фильтрация) получают `lecture_context` отдельно от `current_material`:

- `lecture_plan` — до 20 пунктов явно показанного или произнесённого плана;
- `covered_topics` — названия последних 20 распознанных разделов;
- `recent_summaries` — пять последних кратких резюме;
- `previous_block_summary` — до 20 слов о последнем успешном блоке;
- `previous_block_failed` — признак, что непосредственно предыдущий блок пропущен.

Модель возвращает `context_summary` вместе с конспектом в том же ответе.
Дополнительного вызова для пересказа нет. `lecture_plan` также возвращается в
этом ответе, только если план действительно присутствует в текущем материале.
До распознавания первого плана список пуст; последующие запросы получают найденные
пункты. Это не готовое оглавление всей лекции и не история полных ответов.
Код ограничивает длину резюме и списков, чтобы история не росла с длительностью видео.
У старых результатов без резюме используется краткий список названий заметок.

Контекст помогает ориентироваться, но модель должна подтверждать новые выводы
источниками текущего блока. История может содержать ошибки; правила находятся в
`video_descriptor/prompts/context_ru.txt`. Контекст сам по себе не гарантирует
объединение одинаковых тем в оглавлении и не отменяет ограничения генерации.

История последовательно восстанавливается и из кэшированных блоков.
`context-input-<ключ>-<блок>.json` сохраняет контекст до обработки блока,
`requests/` — фактический запрос с ним. Кэш запросов зависит от снимка контекста:
исправление предыдущего блока может потребовать переобработки следующих блоков,
пока новая история не совпадёт с прежней. Короткая история постепенно вытесняет
старые разделы, а явно найденный план сохраняется.

`--without-context` отключает передачу истории; параметр доступен также в пакетном
скрипте. Новый режим использует отдельные ключи анализа: прежние результаты остаются
на диске, Whisper и OCR сохраняются. Перевод субтитров работает отдельно без этой
истории, чтобы не подменять содержание отдельных реплик конспектом.
