# Обработка без анализа изображения

Используйте экран записи `/create`: на этапе **Конспект** выберите материал
**По речи**. Для аудиофайлов это единственный доступный вариант. Речь, конспект, отчёт и перевод
подготавливаются обычной очередью; готовое распознавание повторно не запускается.
Старые ссылки `/speech?job=…` и `/speech?folder=…` открывают ту же мастерскую.
Существующие результаты распознавания сохранены; для получения конспекта старого
варианта нажмите **Построить конспект** в мастерской.

CLI без кадров: `python -m video_descriptor data/recording.wav --audio-only --model MODEL`.
Параметр `--vision off` продолжает означать OCR и речь, поэтому для полного пропуска
анализа изображения нужен именно `--audio-only`.

Ниже — описание обработчиков и форматов распознавания. Раздел о прежних правках
реплик описывает сохранённые данные и API; отдельный интерфейс `/speech` заменён
общей мастерской.

Обработчики:
- Whisper small NPU: многоязычный текст через Windows worker на 8766, отдельно
  либо с голосами pyannote на Intel GPU. URL: SPEECH_NPU_URL (по умолчанию
  http://host.docker.internal:8766). Перед запуском проверяется здоровье сервиса:
  protocol=1, small, multilingual=true, NPU, static, beam=1. На CPU не переключается.
  Блоки до 300 сек; invalid timestamps приводит к уменьшению блока до 30 сек.
  Перед новым запросом Silero VAD на CPU выделяет речь (минимум 100 мс,
  отступ 400 мс; паузы до 2 сек объединяются). NPU получает только эти участки.
  Блок без речи сохраняется как завершённая пауза без обращения к NPU.
  Таймкоды ответа возвращаются на исходный таймлайн, исключённые паузы не
  сдвигают последующий текст. VAD не распознаёт слова и не назначает голоса.
  Его параметры и интервалы записываются в npu-*/vad.json; отдельные запросы
  и ответы — в npu-*/speech-*/. Уже завершённый кэш не пересчитывается.
  Очень короткая речь может быть пропущена; параметры задаются в speech_npu.py.
  Завершённые ответы и параметры сохраняются в npu-*/response.json / request.json.
  При продолжении готовые блоки, включая уменьшенные, не отправляются заново.
  При изменении NPU-модели или режима нужно создать новый вариант.
  Если ответ содержит words, используются настоящие таймкоды слов. Сейчас сервис
  выдаёт segments: вся реплика получает голос с максимальным пересечением времени.
  Смена человека внутри реплики не разделяется; интерфейс показывает ограничение.
  Границы слов не придумываются. Это локальный режим, Gemini API не используется.
  В режиме NPU → GPU после готовности общего WAV транскрибация и диаризация
  запускаются одновременно на разных устройствах. Статус/журнал показывают оба
  этапа. Текст появляется по мере завершения NPU-блоков; голоса назначаются после
  завершения обоих этапов. Примерное время обработки определяется более медленным
  этапом, но CPU и память общие, поэтому ускорение не гарантируется заранее.
  Каждый этап сохраняет свой кэш. Если NPU падает, уже начатая диаризация завершается
  и сохраняется, затем задание отмечается ошибкой. При продолжении её не повторяем.
  Текущий уже запущенный процесс не переключается; параллельность применяется
  к новым заданиям или продолжению после перезапуска.
- Gemini: текст → Intel GPU: голоса всей записи. Gemini получает аудио блоками
  по 15 минут с таймкодами слов, без облачных меток говорящих. Затем pyannote
  обрабатывает всю запись на XPU; слова получают единые метки по пересечению времени.
  words.json сохраняется до назначения голосов; response.json каждого блока
  повторно используется после сбоя диаризации. Требуется .venv-diarization-xpu.
- Whisper small CPU → Intel GPU: голоса. Полностью локальная схема с XPU для
  pyannote; многоязычная транскрибация пока выполняется Whisper на CPU.
- Gemini 3.5 Transcribe: речь, таймкоды слов и метки голосов; использует ключ из
  существующих настроек Gemini. В Google отправляется аудио. Тариф определяется
  проектом ключа. Блоки до 15 минут; метки разных блоков независимы, в интерфейсе
  явно указано «Блок N». Автоматического сопоставления людей между блоками пока нет.
- Whisper small multilingual: локальный CPU int8; русский, украинский/английский,
  автоматическое определение языка. Сохранение готовых блоков по 5 минут.
- Whisper + pyannote community-1: тот же текст, затем локальная разметка голосов
  по всей записи. Метки слов назначаются по пересечению времени с exclusive-разметкой.
  Без пересечения остаётся unknown. Сегменты ограничены примерно 20 сек для просмотра.

Видео остаётся плеером. Пропускаются только кадры и OCR; затем общая очередь
создаёт конспект, отчёт и перевод, используя готовую речь выбранного обработчика.
Аудиофайлы также воспроизводятся в плеере. Ползунок и клики на время связаны с текстом;
галочка отключает автоматическую прокрутку при самостоятельном чтении.
Имена говорящих сохраняются отдельно от исходных меток, после завершения обработки.
После завершения у каждой реплики доступна кнопка «Изменить / разделить».
Можно исправить текст и назначить другого говорящего из списка.
Для разделения поставить курсор на границе текста и нажать «Разделить по курсору»:
у каждой части появится собственный текст и говорящий. Граница времени выбирается
ползунком внутри исходной реплики, вручную в формате ЧЧ:ММ:СС или кнопкой
«Взять позицию видео». «Послушать перед границей» помогает проверить смену голоса.
Начало первой и конец второй части сохраняются; временная граница общая.
Время не вычисляется из длины текста: его подтверждает пользователь.
Правки хранятся в transcript-edits.json, исходный speech.json и ответы моделей
сохраняются. Разделённую часть можно снова разделить. Одновременная правка
устаревшего варианта отклоняется; нужно обновить страницу.
Повторный запуск создаёт новый результат; предыдущие варианты остаются в списке.
«Продолжить из кэша» после ошибки использует прежнее задание и готовые блоки.
Если прервать диаризацию посередине, сам этот этап начинается заново; текст сохраняется.

Результаты: output/speech-<job-id>/speech.json, requests в chunk-*/request.json,
полные ответы в chunk-*/response.json и usage в measurement.json.
Журнал: output/jobs/<job-id>/run.log. Общее извлечённое аудио повторно используется
по пути, размеру и mtime источника. Частично скопированные записи отклоняются при
несовпадении длительности извлечённого аудио.

Для локальных голосов нужен CPU PyTorch и pyannote.audio. Изолированное окружение:

```bash
python -m venv --system-site-packages .venv-diarization
.venv-diarization/bin/python -m pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu
.venv-diarization/bin/python -m pip install pyannote.audio
```

Принять условия https://huggingface.co/pyannote/speaker-diarization-community-1
и сохранить read-токен в игнорируемый .env.huggingface строкой HF_TOKEN=….
После загрузки моделей аудио обрабатывается локально. Английский Windows/NPU-воркер
не используется этим режимом; многоязычный NPU подключается отдельно на 8766.

Готовые тестовые 15 минут «Фригг» импортированы как speech-frigg-test-gemini и
speech-frigg-test-local. Полный исходник не запускался автоматически.

## GPU: состояние текущего devcontainer

В исходном CPU-профиле /dev/dri и /dev/dxg отсутствовали; CUDA/XPU были недоступны.
В текущем Intel GPU-профиле проброс /dev/dxg и вычисления XPU проверены.
Переключение имени устройства без проброса не работает.
Для Intel Arc нужен PyTorch XPU, доступ WSL/Docker к GPU и проверка операций pyannote.
Проверка хоста из Windows: `wsl --list --verbose`, затем проверить `/dev/dxg`
в соответствующем дистрибутиве. Не заменять CPU-окружение, пока доступ не подтверждён.
Справка: https://docs.pytorch.org/docs/2.14/notes/get_start_xpu.html

На хосте /dev/dxg подтверждён в Ubuntu и docker-desktop. Подготовлен отдельный
XPU-эксперимент и профиль контейнера; дальнейшие шаги в [diarization-xpu.md](diarization-xpu.md).

GPU-проверка на том же 900-секундном WAV завершена: 158.84 сек против прежних
1059.24 сек на CPU. Все 232 exclusive-интервала и метки совпали. Это сравнение
с предыдущим запуском, а не замер с идентичной фоновой нагрузкой. В UI XPU-режимы
используют отдельный Python; при недоступном GPU завершаются ошибкой, не подставляют CPU.
Измерение каждого нового запуска: diarization-measurement.json; журнал этапов:
output/jobs/<id>/run.log. Прогресс-бар во время диаризации показывает занятость,
а точный шаг/процент отображается в статусе и журнале.

## Восстановление остановленного NPU при работающем GPU

Если NPU уже остановился, а GPU ещё сохраняет начатую диаризацию, можно
продолжить только транскрибацию, не прерывая GPU:

```bash
python -u -m video_descriptor.speech_resume output/jobs/<job-id>/job.json
```

Для фонового запуска перенаправить вывод в отдельный журнал и использовать
`nohup` или управление процессом. Пример текущего журнала: `npu-vad-resume.log`
в папке задания. Статус/текст сохраняется в `npu-recovery.json` папки результата;
интерфейс показывает его вместе с текущим GPU-прогрессом. После завершения
обоих этапов задание автоматически продолжится из кэша для объединения результатов.
Повторный одновременный запуск восстановления блокируется файловой блокировкой.
