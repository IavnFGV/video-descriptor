# Проверки Windows-прототипа: 16 октября 2026

Среда: Windows, Python 3.12.10, Intel Core Ultra 7 258V / Arc 140V / Intel AI Boost,
31.5 GiB RAM, существующие OpenVINO 2026.4.1 и GenAI 2026.4.1.0.
Результаты без текста и секретов: [verification-windows.json](verification-windows.json).

## Реальный конвейер

Из исходного `Фригг.mp4` FFmpeg создал короткий (20 s) и длинный (900 s) MP4,
с копированием исходного видеопотока и AAC-аудио. Это настоящее видео и речь,
а не подстановка заранее готового текста. Третий MP4 — 30 s чёрного кадра и тишины.

Файлы загружались через HTTP API в новую изолированную очередь; затем работали
FFmpeg/PyAV, CPU Silero VAD, настоящий HTTP Whisper small FP16 NPU,
сохранение сегментов и экспорт. Облако в этих прогонах не использовалось.

| Проверка | Измеренный результат |
|---|---|
| 20-секундный MP4 | 2.34 s, 1 сгруппированная реплика, корректные границы/ID |
| 900-секундный MP4 | 39.47 s, 56 сгруппированных реплик, корректные границы/ID |
| 30 секунд тишины | 2.22 s, 0 реплик, no_speech=true, пустой SRT и VTT header |
| Экспорт | HTTP 200 для SRT/VTT; правка отражается в новом экспорте |
| Правка | Текст/границы сохранены; исходный speech.json побайтно неизменён, ID сохранён |
| Устаревшая правка | Повтор старого revision отвергнут HTTP 400 |
| Retry после ошибки финализации | Завершённый speech.json переиспользован без изменения; статус снова done |
| Остановка во время длинного задания | HTTP 409, очередь продолжила работу |
| Повторный запуск UI | Та же instance identity, второй сервер не создан |
| UI в браузере | Реплики, плеер и диалог правки; через UI сохранены start=2.8/end=19.7 |
| Фоновый старт NPU | Проверен запуск из UI API через существующее окружение; health ожидаемого профиля |

Время включает upload → результат очереди, извлечение аудио и VAD на этой машине,
но не включает предварительную подготовку проверочного MP4 или загрузку NPU-модели.
Это **не** сравнение движков, WER/DER-оценка, тест батареи или clean-machine benchmark.
Сегменты группируются приложением; число строк не равно числу сырых Whisper chunks.

## Автоматические проверки

Набор `tests/` проверяет кэш/checkpoint, повторный запрос после обрыва,
VAD и восстановление исходной шкалы времени, неверные границы, редактор,
API, версии, отчёты, экспорт и очередь. Новые Windows-проверки охватывают
реальную межпроцессную блокировку, выбор Python, изоляцию workspace,
отказ остановки активной очереди, исправление таймингов и стабильный ID,
смену языка при существующем кэше, end=-1 и ошибку до подготовки аудио.
Итоговые числа и команды фиксируются в JSON/README после завершения проверки.
Финальный результат: **157 passed, 1 skipped**, Ruff и `pip check` без ошибок.

Единственный ожидаемый пропуск — symlink-проверка без Windows
SeCreateSymbolicLinkPrivilege. FFmpeg scene-selection проверен с установленным
imageio-ffmpeg binary; исправлена Windows-проблема пути метаданных внутри фильтра.
Проверка защиты
встроенного исходника выделена отдельно и выполняется даже без права создавать symlink.
POSIX 0600 assertion неприменима в Windows; секретные настройки используют NTFS ACL
каталога, не отдаются HTTP API и не включаются в Git.

## Ограничения и наблюдения

- Не проверены новая Windows GPU-диаризация, перевод/конспект через Ollama,
  EN/UK/mixed-language качество, монтаж/музыка/долгие записи за пределами 15 минут.
- Установленный Windows torch — CPU, pyannote отсутствует; OpenVINO GPU listing
  не является доказательством готовности PyTorch XPU.
- Нет нового ручного эталона для WER/DER. Скорость сама по себе не подтверждает точность.
- Восстановление после завершённой речи проверено реально; обрыв посередине HTTP/NPU
  покрыт тестами с имитацией. Аппаратный crash и power loss здесь не провоцировались.
- Начальная попытка общего `pytest` обнаружила исторический скрипт внутри `output`;
  он выполнил диагностический запрос к Gemini при импорте. Изменённые request/upload/response
  JSON восстановлены из WSL. Теперь pytest собирает только `tests/`; данный инцидент
  не входит в локальные end-to-end замеры выше.
- При первой фоновой подготовке NPU readiness не появилась. Повторный контролируемый
  запуск с явным bind и журналом прошёл; добавлен монитор кода выхода, чтобы не скрывать
  последующие ошибки. Причина первой незавершённой подготовки не установлена.
- Проверены установка поверх существующей venv и создание desktop-ярлыка. На этой
  машине WScript не смог сохранить shortcut сразу в локализованный OneDrive Desktop;
  installer теперь сохраняет его в runtime и копирует в известный Desktop через Unicode API.

## Следующий минимальный этап

Отдельный Windows XPU probe с совместимыми torch/torchaudio/pyannote и имеющейся моделью,
сначала на 60 s, затем 900 s того же аудио и сравнением с CPU. Не менять `.venv-npu`.
Если потребуются новые веса или системный драйвер — сначала показать размер/изменение
и получить согласование. После этого включить режим говорящих в простой UI и проверить
перевод/конспект, затем спроектировать подписанный installer и clean-machine испытание.
