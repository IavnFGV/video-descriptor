# Создание конспекта в браузере

Запустите локальный сервер из корня проекта:

```bash
python -m video_descriptor.serve --bind 127.0.0.1 --port 8000
```

Откройте `http://localhost:8000/create` или нажмите **Новая запись** на главной
странице. Выберите аудио или видео, либо готовый файл из `data`, при желании
задайте название и нажмите кнопку создания. Файл загружается потоково,
без удерживания целиком в памяти; поддерживаются MP4, MKV, MOV, WebM, WAV, MP3,
M4A, FLAC и OGG до 4 ГБ. Запись сохраняется в `data/uploads/<id>/<исходное имя>`.

На этапе **Конспект** стратегия **По речи** выключает извлечение кадров и OCR.
Стратегия **По речи и тексту слайдов** добавляет распознанный текст слайдов. Речь, конспект, отчёт и перевод остаются общими.
Для аудиофайлов доступна только стратегия по речи. Без кадров конспект собирается
из речи блоками по времени. Выбор обработчика речи и сохранённые варианты
доступны на этой же странице; старый адрес `/speech` перенаправляет в `/create`.

Задание помещается в очередь в `output/jobs/`. Независимый рабочий процесс
обрабатывает задания последовательно, ожидая завершения уже запущенного CLI
в этом контейнере. Закрытие страницы или перезапуск HTTP-сервера не останавливают
рабочий процесс. Остановка контейнера/компьютера остановит обработку; готовые
этапы сохраняются. При следующем запуске рабочего процесса прерванное задание
будет явно помечено ошибкой. Кнопка **Продолжить из кэша** повторяет то же задание
с тем же видео и параметрами, сохраняя доступный кэш.

Очередь работает и в Windows, и в Linux: межпроцессные блокировки реализованы
в `platform_support.py`, проверка процессов использует Windows process API либо
Linux `/proc`. Модель и стадии зависят от выбранного действия и сохранённых
настроек; модель не назначается автоматически по наличию сервера.
Пакетный `scripts/process_videos.py` отдельно использует default `qwen3.5:9b`
и запускает перевод после анализа; это не универсальный сценарий desktop UI.

## Что видно во время обработки

- Активный шаг: проверка, речь, слайды, конспект, отчёт, перевод.
- Реплики Whisper с временем из `transcript.partial.json`.
- Выбранные изображения и OCR из `frames.partial.json`.
- Проверенные заметки завершённых блоков из `notes-live.json`.
- Текущая задача модели, полученный объём ответа, картинки и время запроса.
- Панель **Что отправили модели**: точный промпт, контекст лекции, материал
  конкретной задачи, прикреплённые изображения, схема ответа и параметры.
- Поток рассуждений и незавершённый ответ из журнала `events.jsonl`.
- Ошибки отдельных фрагментов и ссылка на отчёт, когда он появился.

Обновление происходит раз в две секунды. Это реальные промежуточные результаты;
новый текст появляется, когда его возвращает Whisper или модель. Проценты относятся
к текущему шагу, а не к прогнозу общего времени. Отдельный шаг может занимать долгое
время до первого результата, например извлечение аудио или отбор кадров FFmpeg.

Речь и кадры слева показывают исходный фрагмент для просмотра, а не состав запроса.
Например, при фильтрации модель получает уже созданные заметки, а при выборе
картинок — текст и OCR. Панель запроса читает `requests/<id>/request.json` и
показывает именно отправленный материал. Изображения загружаются только при
раскрытии панели и один раз на запрос; они не пересылаются при каждом опросе
прогресса. Можно открыть полный JSON со всеми полями и изображениями.

**Следовать обработке** держит видео на позиции текущего материала, с выключенным
воспроизведением; при переходе к следующему шагу позиция может вернуться к началу.
Выключите этот режим, чтобы смотреть видео самостоятельно. Ползунок и кнопки
таймкодов позволяют перейти к реплике или кадру. Скорость вычислений не меняется.

У старых запусков из терминала тоже можно смотреть прогресс через список
**Уже обрабатывается?** или ссылку **Ход обработки** на главной странице. Статус
берётся из существующего лога и файлов. Если старый процесс не публикует проверенный
конспект по ходу работы, показанные блоки помечаются как черновики; окончательный
конспект появится после завершения анализа.

## Рассуждения модели

Флажок **Включить рассуждения модели** задаёт `think: true` для запросов анализа
нового задания. По умолчанию выключен; перевод остаётся в прежнем режиме.
Передаваемые моделью рассуждения показываются как обычный текст и сохраняются
в журнале. Если модель их не передаёт, выдуманного текста в интерфейсе нет.
Этот режим может увеличить время работы и расход бюджета генерации.

Для продолжения запуска из терминала с тем же режимом повторите прежнюю команду.
Чтобы продолжить с рассуждениями, добавьте `--think` к прежней команде:
Whisper, OCR и завершённые блоки анализа сохраняются. Этот флаг задаёт режим
только для запросов, которых ещё нет в кэше; он не меняет ключ готовых блоков.
Незавершённый запрос повторяется целиком. Рассуждения готовых блоков задним числом
не создаются.

В карточке **Работа модели** галочка **Рассуждения в следующих запросах** меняет
режим во время обработки. Настройка сохраняется в `analysis-control.json` в папке
результата и читается перед каждым запросом, включая повтор после лимита. Уже
отправленный запрос не меняется и не прерывается. Настройка сохраняется при
перезапуске и имеет приоритет над начальным `--think`; готовый кэш не меняется.
Переключатель применяется также к следующим запросам перевода в этой папке.

Экран написан на обычных HTML/CSS/JavaScript, без отдельного frontend-сервиса и
npm bundler. Production CSS собирается из общих источников через
`scripts/build-ui-css.py`; проверка синхронности — с `--check`.
Код очереди — `jobs.py`, чтение промежуточных результатов — `live.py`, HTTP API —
`serve.py`, интерфейс — `assets/create.*`. Загруженное видео и все результаты
остаются в workspace; выбранному Ollama/LM Studio отправляется материал запроса.
При выборе Gemini соответствующий материал отправляется Google; удалённый Ollama
также не является полностью локальной обработкой.

## Восстановление после падения процесса Ollama

Повторы и пропуск блоков ниже относятся к legacy lecture/CLI-анализу. Конструктор
материалов отдельно валидирует результат и предлагает ручное восстановление
неверного ответа; не считайте ошибочный конспект автоматически готовым.

Для перевода можно явно проверить CPU: `python -m video_descriptor.translate
"output/<папка>" --local-model qwen3.5:9b --device cpu`. `--local-model` закрепляет
Ollama-модель независимо от сохранённого провайдера; `--model` — лишь legacy default,
который не заменяет уже сохранённый выбор. Параметр устройства передаёт `num_gpu: 0`
в Ollama. `--device auto` (по умолчанию) возвращает автоматический выбор устройства.
Готовый перевод остаётся совместимым с кэшем при смене устройства. Для сравнения
скорости нужны одинаковый материал, параметры и проверка фактического размещения
модели через `/api/ps`; загрузку модели следует учитывать отдельно от генерации.

При ошибке соединения, HTTP 500/502/503 или незавершённом потоке программа делает
до двух повторов именно текущего запроса. Перед повтором модель выгружается через
API Ollama (`keep_alive: 0`); следующий запрос загружает её заново. Все попытки
остаются в журнале. Запросы анализа используют одинаковый размер контекста
16 384 токена, чтобы переход между выбором кадров, конспектом и фильтрацией
не вызывал перезагрузку процесса модели. Если повторы не помогли, блок отмечается пропущенным, работа
продолжается. Эта мера не заменяет диагностику журнала Ollama на компьютере.

При повторном запуске можно добавить `--reuse-completed-blocks` (в CLI или
`scripts/process_videos.py`). Пропущенные блоки повторяются, а готовые блоки
используются вместе с контекстом, с которым они были созданы. Это позволяет
исправить пропуск без пересчёта всех последующих блоков; их старые краткие резюме
не переписываются с учётом исправленного материала. Без флага остаётся обычная
проверка соответствия кэша текущему накопленному контексту.

## Единый интерфейс записи

Текущая оболочка использует общую верхнюю строку **Файл / Вид / Инструменты / Справка**
без sidebar. **Файл → Записи** открывает библиотеку. В открытой записи видео и
расшифровка показаны рядом, на узком окне — друг под другом. **Вид** доступен только
в открытой записи: он управляет панелями и компоновкой, не удаляя данные/черновики.
По умолчанию материалы и технические сведения скрыты; включите нужную панель.
Перевод убран из UI; новые конспекты не запускают его дополнительно. Сохранённые
данные и backend остаются; границы — в [описании перевода](translation-providers.md).

Исходные stage IDs/query `source`, `speech`, `notes` сохранены для совместимости.
До выбора записи они используются формой создания, но в открытой записи прежняя
полоса трёх этапов скрыта: это уже не три обязательных последовательных экрана.
Сведения об исходнике и название доступны при общем плеере, правки реплик и
участников — при расшифровке.
Конспект и статья имеют отдельные вкладки и списки версий, но используют один
редактор с защитой несохранённых правок. Ключи и подключения открываются через
общие **Инструменты → Настройки AI**, не через старый диалог записи.

Выбор обработчика речи применяется и к видео со слайдами. Стратегия по речи
не извлекает кадры; стратегия со слайдами использует текст OCR, а не картинки
и не целое видео. Нативный просмотр видео Gemini в этот интерфейс ещё не добавлен.

**Создать новую версию речи** запускает только распознавание в новой папке.
**Создать новую версию конспекта** копирует выбранную сохранённую речь, её правки,
перевод и кадры в отдельную папку и строит новый конспект. Старый результат и его
`notes.user.md` сохраняются. Пока новый конспект строится, доступен предыдущий.
Версия расшифровки выбирается независимо от версий конспекта и статьи;
выбор материала не переключает речь. Другие записи открываются через **Записи**.
Старые вложенные варианты `auto` / `off` доступны в выборе варианта конспекта.

На этапе **Конспект** кнопка **Создать новый конспект** открывает настройки;
запуск использует готовую речь, её правки и перевод без повторного распознавания.
Кнопка **Удалить конспект** удаляет только выбранный конспект и ручные правки
после подтверждения. Расшифровка, перевод, имена голосов, субтитры и кадры
сохраняются. Настройки остаются доступны для нового запуска. Для вложенных
вариантов `auto` / `off` удаляется только выбранный вариант.

Действие **Удалить версию целиком** находится в меню **⋯** рядом со списком.
Оно удаляет папку результата с расшифровкой, конспектом и правками после
подтверждения. Исходный файл и другие версии сохраняются. Во время обработки
этой записи оба вида удаления запрещены; задания удалённой целиком версии
скрываются из очереди и недоступны для повторного запуска.

Старые `/speech` и ссылки на `report.html` ведут в общий экран. Редактор отчёта
используется внутри него; Markdown и сохранение работают через прежний API.
Несохранённые правки блокируют переключение записи, пока их не сохранить.
